# IRON SQUAD インターフェース整理

2026-10-07 / v1.26.0 / Service Worker v82

## 画面の構成

| 画面 | 最初に表示する内容 | 開いて確認する内容 |
| --- | --- | --- |
| 戦況 | 隊長の姿、HP、実戦・予備人数、要救助人数、時刻、軍令、一括治療、各管理画面への入口 | 前回の作戦報告、隊長の成長・覚醒、整備・昼夜・救助の説明、セーブ選択 |
| 部隊・装備 → 兵士名簿 | 所属別の名前・職・レベル・HP・状態。名前・職・小隊の検索と負傷者フィルター | 1名ずつ詳細を展開。援助・昇格・強化・放逐・個人記録・全7部位の装備譲渡 |
| 部隊・装備 → 雇用 | 募集候補と本隊・自部隊への雇用操作 | 候補再募集 |
| 部隊・装備 → 隊長装備・バッグ | バッグの部位・上昇項目フィルター、比較、装備・強化・売却選択 | 現在の隊長装備（全7部位）、強化引継ぎの比較と旧装備消滅の警告 |
| 国家 | 軍令、国庫寄付、危険度別の遠征と小隊状況 | 派遣兵士の選択、共有装備箱、前回の財政報告 |

ヘッダー、タブ、戦場へ戻るボタンを固定。本文を一つの領域でスクロールする。兵士名簿とバッグ、共有箱の独立した短いスクロール枠をなくした。詳細記録と譲渡は独立したウィンドウで表示する。

## 表示・操作の変更

- 青灰色の背景、明るい本文、金色の見出しと選択状態に統一。上昇は緑、低下や危険は赤で、矢印・数値・文言も併記。
- 名簿は通常状態で48名の操作や装備を展開しない。開いた兵士を更新後も維持する。他の兵士を開くと前の兵士を閉じる。
- バッグの「上昇項目あり」は、少なくとも一項目が上がる装備を表示する。強化引継ぎ後も含む。別の能力が下がる場合は比較欄の赤い↓と差分を確認する。
- 売却選択はフィルター変更後も保持。売却ボタンは見えていない品も含めた選択数・金額を表示する。装備中や保護済みの品の売却条件は既存ルールを使用する。
- 詳細・譲渡の表示中は背面を `inert` にし、手前のウィンドウ内でフォーカスを保つ。Escapeで手前だけを閉じる。閉じたら元の操作へフォーカスを返す。
- 戦闘画面はHP・期・残り時間・直属/本隊人数を常時表示。現在地・危険度・昼夜を小さく表示。管理用の残高は司令部のヘッダーに集約。
- 強襲・入口・作戦切替バナーを縦並びの同じ領域へ移動した。高額装備の装備名・保護・引継ぎ警告は保持。
- スマホの検索入力とセレクトは16px。360px以下と横向きの高さ500px以下のレイアウトを用意。外部フォントや追加画像のダウンロードは不要。

## 検証中に修正した既存の不具合

1. `startFreshGame()` にセーブ変数 `saved` の参照が混入し、新規開始で例外になっていた。遠征復元は `resumeSavedGame(saved)` の小隊初期化直後へ移動。
2. 隊長の多段階覚醒が実装されている一方、UIは最初の覚醒後にボタンを非表示にしていた。既存のクラスアップルールから現在職・次職・素材を表示するよう変更。
3. 隠されていた現在地・昼夜バッジは更新コードに接続されていなかった。再表示に合わせて現在地・昼夜・防御不足の状態を更新するよう修正。

### 2026-10-07 タブ内容の混在修正 (v1.27.3 / SW v87)

「国家」の選択表示に対しバッグが残る不具合を、親パネルの配置検証で再現した。本文を未接続のDOMへ移動した後のID取得が失敗していたため、移動前に部隊・装備・寄付・共有箱のノード参照を保持するよう修正。部隊・装備は部隊の配下、寄付・共有箱は国家の配下に移動される。装備のサブタブでは名簿領域ごと隠し、経験の説明も名簿のみに表示する。

回帰テストは、全タブの祖先を含むCSSの非表示判定、各部隊サブタブから国家・戦況への往復、国家で操作後の再描画を確認する。タブボタンの選択色や親パネル自身の `.hidden` だけでは、親の外に残った内容を検出できないため、パネルの所属も確認する。

## 検証結果と制限

### 実行した検証

- `tests/interface.test.mjs`：実際の `setupUI()`、新規開始、会議表示をjsdomで実行。全IDの一意性、タブ移動、48名の一覧、1名展開、展開状態の保持、検索・負傷者絞り込み、装備フィルターとCSSの非表示判定を確認。
- 同じDOMテストで既存の装備交換・売却処理、7部位の譲渡画面、寄付・治療のハンドラー、手前のウィンドウからのEscape終了、背面の操作制御を確認。
- 遠征の参加兵選択・危険度変更・実際の派遣・セーブ再開後の遠征復元を確認。多段階覚醒ボタンと宝玉不足、HP警告色・時刻・待機残秒の表示を確認。
- `tests/performance-regression.test.mjs`、`tests/field-form.test.mjs` を実行し成功。戦闘更新・セーブ・描画の既存回帰確認も通過。
- JavaScript構文、Service Workerの追加アセット、ローカルHTTP配信を確認。

### 未確認

ブラウザ操作用接続から利用可能なブラウザが取得できなかったため、実際のブラウザ描画、スマホ実機、縦横切替、端末固有の字体・安全領域は未確認。jsdomには実画面のレイアウト計測がないため、重なりや文字切れが実機でないことまで確認済みとは扱わない。

今回のDOMテストはメモリ上のセーブを使用し、実際のプレイヤーセーブを変更しない。古い人数・世界寸法・旧救助仕様を前提とする他のテストについて、この変更で全件成功したとは扱わない。

## 再実行

Node.jsとjsdomが必要。jsdomは開発時の検証専用で、ゲームの実行には不要。

```powershell
node tests/interface.test.mjs <jsdomがインストールされたディレクトリ>
node tests/performance-regression.test.mjs
node tests/field-form.test.mjs
```

今回の環境では、無視対象の `__pycache__/ui-tools/node_modules` にjsdomを配置したため、引数なしで実行できる。`UI_REVIEW_DIR` を設定すると、実際に生成されたDOMの静的HTMLを出力する。これは表示検証の資料で、ゲーム操作が動くブラウザのスクリーンショットではない。

表示の変更は `interface.js` と `iron-squad-interface.css`。本文の大きな旧HTMLを一度に置き換えず、アクションを持つ既存ノードを移動することでイベントとIDを維持した。追加CSSは既存テーマの後に読み込む。既存の戦闘人数、敵数、装備の売却条件、120秒の作戦・8秒の待機、所持品とセーブ形式は現行コードを引き継ぐ。
