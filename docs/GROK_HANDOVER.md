## 1. プロジェクト概要 & 技術スタック

### 1.1 プロジェクト方針
- **「自分のiPhoneで快適・爽快に遊ぶことだけを追求した個人専用ゲーム工房」**
- PWA（Progressive Web App）仕様。iPhone Safariの「ホーム画面に追加」でアドレスバーや下部タブなしの全画面ネイティブアプリ同等で稼働。
- 外部ライブラリ（React, Vue, Phaser, Pixi等）を一切使わず、**Vanilla HTML5 / Modern ES Modules / Canvas 2D / Web Audio API** のピュアWeb技術のみで構築（超軽量・高速60fps・完全制御可能）。

## 4. grokが開発・編集する際の最重要開発ルール

grokが作業を引き継いでコードを編集する際は、以下の約束事を厳格に遵守してください：

### ⚠️ ルール1: スタック・ブラケット整合性の絶対遵守
- `js/games/iron-squad/index.js` は約 7,880行 の単一巨大モジュールです。
- メソッド追加・編集時に閉じ括弧 `}` の過不足が発生するとゲーム全体がロード不能になります。
- 編集後は必ず括弧の一致（スタック検証）を確認すること。

### ⚠️ ルール2: キャッシュバスターの同時更新（PWA対応）
- JS / CSS を更新した際は、iPhone Safariで即座に反映されるよう、以下を必ずセットで更新すること：
  1. `sw.js`: `CACHE_NAME = 'mobile-game-studio-vXX'`（数値を+1）
  2. `index.html`: `iron-squad.css?v=XX`, `game-ui.css?v=XX`, `app.js?v=XX`, フッター表記をその出荷バージョンへ。現行はキャッシュ v53、フッター v1.21.0。

### ⚠️ ルール3: 画面遮蔽を避ける（iPhone縦画面の視界保護）
- 戦場Canvas上に巨大な固定UIや常時重なるピルバッジを配置しないこと。
- 通知テロップは画面中央を避け、下部の `battle-log-window` またはスマートなヘッダー統合を活用すること。

### ⚠️ ルール4: 60fps負荷管理（オブジェクト・メモリ）
- 毎フレームの `render()` や `update(dt)` 内で新しいオブジェクト（`{}`）や配列（`[]`）を大量に生成しないこと（GC詰まり防止）。
