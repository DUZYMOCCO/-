# 給与・整備手当・国家財政 — v3.1.2の履歴 / SW v129

> v4.0.0では、国家収入に応じて給与を配分する方式へ改訂。以下は旧仕様と当時の検証履歴。現行は [V4_NATIONAL_ECONOMY.md](V4_NATIONAL_ECONOMY.md)。

## 調整の狙い

装備の強化が無限に続く世界で、給与20G・首位手当50Gが固定だったため、育成後の強化を給与だけでは続けられなくなっていた。強化価格と装備性能の無限成長を保ち、給与も現在の整備費へ追従させる。

従来のランカー手当は兵士のサイフへ加算するだけで、国庫から引かず、財政台帳にも記録していなかった。通常給与・整備手当・栄誉手当を同じ支給計画で確定し、すべて国庫から実際に支払う。

## 通常給与

- 基本給：`20 + (Lv - 1) × 6 + 昇格段階 × 40 + 国家発展Lv × 20` G／期。
- 整備手当：装備中の品の次回強化費を平均し、その60%を切り上げて加算。武器は重み2、他の部位は重み1。未装備と重複した同じ品は数えない。
- 通常給与は基本給＋整備手当。全装備が同じ強化費なら、十分に育った一般兵でも約1.67期の給与で次の1段へ進める。装備の強化度が不揃いなら、武器を重く見た装備一式の平均に基づく。
- 出撃兵・予備兵・負傷兵に支給。討死した兵と名簿内の同一人物の重複は支給対象外。期末に実戦履歴を確定し、新兵補充の前に支払う。

強化費は従来と同じ `floor((20 + 強化段 × 18 + 強化段^1.4 × 6) × max(1, 性能ランク × 0.8))`。隊長・兵士・公費・工房・寄付後の整備で同じ計算を使用する。上限を設けない。

## ランカー手当

各部門の1位／2位／3位に通常給与の50%／30%／20%を切り上げて加算。序盤の最低額50G／30G／20Gを保ち、大きい方を支給する。複数部門の手当は従来どおり加算する。実戦・回復等の履歴のない新兵には栄誉手当を支給しない。

ランキング画面・兵士名簿・個人詳細・給与支払は共通の額を使用する。個人詳細には通常給与の基本／整備内訳と、全該当部門の栄誉手当見込みを表示する。

## 国家財政

- 定期歳入：`3,000 + 期数 × 18 + 全兵士の通常給与・栄誉手当見込み × 1.25 + 指揮手当 + 国家発展Lv × 600`。
- 既存の兵站収入を実際の全給与へ拡張し、25%の運営余力を含める。給与が育っても、固定20Gの人数分しか歳入が増えない状態にしない。
- 指揮手当：従来の`40 + 期数 × 6`に、隊長の武器の次回強化費の30%を切り上げて加算。
- 通常給与を先に支払い、次に栄誉手当を払う。足りなければ各段階で比例配分し、最後の1Gまで決まった順序で配る。国庫は負にしない。
- 軍備・研究・開発では、全給与・栄誉手当・指揮手当の2.5期分、最低6,000Gを備蓄する。
- 装備更新で整備手当やランキングが変わる場合も、更新後の給与を試算して備蓄を守る。都市の昇格で全員の基本給が上がる場合は、昇格後の備蓄を先に確保する。
- 公費軍備予算は既存の上限に、運営余力の30%（均衡）／40%（軍備優先）／15%（発展優先）を追加。高強化の軍隊でも公費の予算だけが固定額で置いていかれないようにする。

財政台帳の`給与支払`にはすべての兵士支給を含める。通常給与・整備手当とランカー栄誉手当は表で分けて示し、二重計上しない。国庫残高の差と、全収入から全支出を引いた額が一致する。

## 保存・拡張の入口

現行保存形式4を保持し、サイフ・国庫・装備・国家発展を初期化しない。新しい給与は次の期末から適用。休息中・保存再開で給与や手当を再支給しない。以前の保存に支給額の履歴がない場合、過去の支給0Gとは表示しない。

| 調整したいこと | 入口 |
|---|---|
| 基本給、Lv・昇格・国家の加算、整備の比率 | `payroll-rules.js` の `PAYROLL_RULES` / `salaryQuote` |
| 強化費の曲線 | `payroll-rules.js` の `equipmentUpgradeCost` |
| 各順位の比率と最低手当 | `troop-rankings.js` の `RANKER_BONUS_RATE` / `RANKER_BONUS_SALARY` |
| 支給の計画・不足時の実支払 | `payroll-rules.js` の `createPayrollPlan` / `paySoldiers` |
| 歳入、備蓄、都市昇格後の余裕資金 | `economy-rules.js` / `nation-rules.js` |
| 公費軍備の配分 | `armament-rules.js` の `ARMAMENT_POLICIES.maintenanceShare` |

難易度の敵倍率・装備性能・基礎能力255上限はこの変更の対象にしていない。実プレイでは兵士の給与と整備が増えるため、従来より育成が進む。
