## 結論

5基本職はすべて「基本職 → 上位職 → 極職 → 伝説職」の昇格先、費用、名称、能力値を持つ。兵士の能力値は第2・第3段階でも伸び、壁通過も有効。ただし、重装・軽装・弓・衛生の固有能力に第1段階の職IDだけを判定する処理が残り、**昇格すると固有技の一部を失う**。隊長は第2・第3段階の名称・費用・説明があるが、能力計算が第1段階の倍率のまま。

見た目も基本職と第1段階の差はある一方、第2・第3段階の専用デザインは未整備。魔法系は3上位段階とも同じ描画。装備による見た目の差とクラスの段階差は分けて判断する必要がある。

比較画像：[クラスアップの描画比較](previews/class-up-audit-20261011.png)。同一人物・同一装備・同一時刻で比較し、兵士のラベルを外して衣装と形状を確認した。

## 実行比較

### 条件

- Nodeの標準入力から一時スクリプトを実行し、JSDOM上で実ゲームの `update()` を使用。検証用localStorageはJSDOM内だけで、ユーザーのブラウザセーブは読み書きしていない。
- 各比較は同じ初期ゲームを復元。兵士は平均才能・同じ属性プロフィール・同じ武器種・同じ配置、十分なHP／MP／弾薬を使用。
- 重装／軽装は剣、弓系は弓、衛生系は杖。移動を止め、攻撃・発射・回復の分岐を比較。
- 衛生のフィールド比較では受傷者のHPを90%に保ち、通常回復魔法の対象選択と区別。バフはクールダウン中にしてフィールドと浄化弾を確認。
- 数値は検証用の人物と初期状態の結果。一般的な固定ステータスを表すものではない。

## 修正優先順

1. **昇格で能力を失う不具合。** 重装の範囲攻撃、軽装のビーム・回避、弓の複数射、衛生のフィールド・浄化弾・高速救助を、職系統と段階に基づく共通ルールへ整理する。第1段階の能力を上位段階で継承するか、代替の上位技へ進化するかを明確にし、実updateで各段階を比較する。
2. **隊長第2・第3段階の能力接続。** 現在段階の定義を能力計算・部隊オーラ・攻撃範囲へ渡す。魔法・衛生・直属等を含む加護の対象を定義し、宝珠・宝玉消費に見合う実差を検証する。
3. **弓系の読込と射程の整合。** 好み武器補正を全弓系に対応させ、保存済みの遠隔好みを維持する。保存している射程倍率を使用するか、既定射程との二重強化を避けるため定義側を整理する。
4. **段階別の衣装・技の見た目。** 全系統の第2・第3段階と魔法上位職、隊長帝皇・神話帝の識別を準備する。顔や人物IDは維持し、装備Tierとは独立して比較する。隊長の頭上職名も現在段階に連動させる。
5. **UI・説明・テストの照合。** 実装されていない技名だけが残る状態を解消し、現在職の固有能力と継承状況を確認できる表示を整える。各段階の攻撃・治療・守護・保存読込・描画の比較を保証する。

技を継承・強化すると戦闘結果や到達地点が変わるため、修正後は通常部隊と勇者パーティの両方で再検証が必要。現時点では上記修正も再バランスも実施していない。
