# 保存の回数を減らす（Codex向け指示書）

**着手条件: `UPGRADE_TAP_CRASH_2026-10-15.md`（背景保存のまとめ）が終わってから。** 同じ `save-slots.js` / `saveGame` を触るため。

## 背景
- `saveGame()` の呼び出しが70か所以上ある。ボタン1つ、イベント1つごとに保存が1回走る。
- 保存1回が重くなった（約600KB の一覧の複製、LZW 圧縮、読み戻し検証）。そのため、回数の多さが停止・メモリ増加・連打での強制終了の原因になってきた。
- ユーザーの意見: 「セーブの頻度がいろんなところで多すぎる」。

## 方針（ユーザー決定）: 保存は「10秒ごとのオートセーブ」と「4つの場面」だけ
- ふだんの `saveGame()`（引数なし、または `background:true`）は**何もしない**（保存しない）。10秒ごとのオートセーブ（背景保存）に任せる。
  - ボタン操作・イベント・期の切替・昼夜などで呼んでいる70か所以上は、すべてこれに当たる。呼び出し自体は残してよい。
- その場で同期保存するのは、次の4つだけ。`saveGame({immediate:true})` のように明示する:
  1. `visibilitychange` の hidden と `pagehide`（アプリを閉じる・切り替える）
  2. ハブに戻る（`btn-back`）・セーブ画面へ移る
  3. 地点セーブ（`saveCheckpoint`。ユーザーが押す保存）
  4. ゲームオーバー・全滅の記録（`state:'fallen'`。落として全滅をなかったことにできないように）
- ほかに、ゲームの始まり（新規ゲーム・再開直後の初期記録）は、記録の土台を作るので今までどおり書く。
- 「書き込み失敗時に操作を巻き戻す」処理（`startPlatoonExpedition`、`toggleSoldierLock` など、v6.11.14 で同期のまま残したもの）も、ふだんの操作として扱いオートセーブに任せる。巻き戻しの仕組みは、保存しないなら不要になるので外す（巻き戻しが要らない形で動作が正しいことを確かめる）。
- メニュー・商人画面・会議などでゲームが止まっている間も、オートセーブの10秒の時計は進め、止まっている間の変更も保存されるようにする（今 `autoSaveClock` がゲームループの中だけで進むなら、別のタイマーにする）。
- オートセーブの間隔は10秒のまま。何も変わっていなくても保存してよい（判定を入れるなら、確実なときだけ省く）。
- 保存失敗の知らせ（容量不足など）は、オートセーブや4つの場面で実際に書いて失敗したときに出す。
- 割り切り（ユーザー了承済みの前提）: 落ちたときは最後のオートセーブ（最大10秒前）まで戻る。お金と装備はまるごと戻るので食い違わない。商人の品ぞろえなどの運の要素を、落として引き直せてしまうのは許容する。

## 確認
- テスト:
  - ふだんの `saveGame()` を何回呼んでも、書き込みは起きない。10秒ごとのオートセーブで最新の状態が書かれる。
  - 4つの場面（hidden/pagehide、ハブに戻る・セーブ画面、地点セーブ、全滅）では、その場で書かれ、古い背景依頼に上書きされない。
  - 遠征派遣・兵士の保護など、巻き戻しを外した操作が正しく動き、オートセーブ後に読み込んでも状態が一致する。
- ブラウザー（CPU 4倍、約600KB のセーブ）で、メニュー操作の連打、休憩、期の切替、戦闘中に、保存による100ms超のフレームが出ないこと。1分あたりの実際の書き込み回数を、修正前と後で記録する。

## 結果
- **通常保存の no-op 化**: 引数なしの `saveGame()` および `background:true` の呼び出しを no-op 化。ボタン操作・期切り替え・昼夜・イベント等の70箇所以上の呼び出しによる頻回保存を完全停止。
- **10秒ごとのオートセーブ（`auto-save.js`）**: ゲームループに依存しない独立タイマーで10秒ごとに `saveGame({auto:true, background:true})` を実行。メニューや商店、会議等でゲーム進行が止まっている間も保存クロックが進行し、安全に最新状態を記録。
- **4つの同期保存場面を厳密化（`immediate:true`）**:
  1. `visibilitychange`（hidden）および `pagehide`
  2. ハブへ戻る（`btn-back`）およびセーブ選択画面へ移る（`showSaveMenu`）
  3. 地点セーブ（`saveCheckpoint`）
  4. ゲームオーバー・全滅の記録（`gameOver` / `state: 'fallen'`）
- **操作ロールバックの撤廃**: 遠征派遣（`startPlatoonExpedition`）や兵士保護（`toggleSoldierLock`）から保存失敗時の巻き戻し機構を撤廃。通常の操作としてオートセーブに委ねる形へ簡素化。
- **検証**: `iron-squad/tests/auto-save.test.mjs` を新設し、通常呼出の書き込みゼロ、即時保存の同期実行、10秒タイマー発火による背景保存、4場面での保存、ロールバック撤廃操作の永続化を検証。全189テストPASS。
