# 工房ティアの解放と個人予算（v5.5.1 / ゲームキャッシュ v191）

工房レベルが満たすのは「作れる装備のティア」だけ。隊長も兵士も、実際の購入には各自の所持Gが必要。工房が成長したときに、全員へ新しい装備を一括で配らない。

## 調達の支払い

- 隊長の工房購入・製作は従来どおり隊長の所持Gから支払う。
- 兵士の新規調達・換装・自動強化は、その兵士の所持Gから支払う。国庫や他の兵士の所持金で肩代わりしない。
- 兵士は自己整備と同じ6Gを残す。空き部位には製造可能な範囲で買える最上位ティアを購入する。最低ティアも買えなければ、その部位は空いたまま。
- 換装・強化も本人が費用を払える場合だけ行う。資金不足の兵士は、強化済みの現在の装備を維持する。換装と強化の対象は従来と同じく1期最大8名。
- 既に持っている共有在庫・戦利品の配布は継続する。新規製造の代金と区別し、所有済みの装備に二重で代金を請求しない。
- 新兵の初期装備と勇者の専用装備は既存のまま。工房成長による無償の最新装備への置換は行わない。

兵士の量産制式品は従来の標準調達費を使用する。例：T1は52G、T21は535G。隊長の購入価格は従来の標準調達費×1.4で、T1は73G、T21は749G。

## 保存と財政表示

個人の実支出を `personalEquipmentProcurement` / `personalForging` に記録し、国庫の支出合計には加えない。国庫は給与・開発・製造技術の研究などを引き続き負担する。国庫の `equipmentProcurement` / `publicForging` は旧版の財政記録として保持する。

兵士ごとに `lastEquipmentPurchase`（期・予算・支出・調達・換装・強化数）を保存。装備は `selfFunded` / 品質表示「自費調達」を付ける。既存の所持品や過去の支給を遡って請求しない。保存後も同じ期の調達を繰り返さない。

国家・工房の画面に「製造可能ティア」と「各自のGが必要」を明記し、国庫の支出と兵士の自費を別々に表示する。

## 検証

工房T21を解放し、次の3名を同時に整備した。

| 所持G | 整備結果 | 残金 |
| --- | --- | --- |
| 0G | 新規購入なし | 0G |
| 58G | T1を1部位購入 | 6G |
| 3,751G | T21を7部位購入 | 6G |

合計3,797Gを、それぞれの財布から実際に支払った。国庫0Gでも、国庫1,000万Gでも、この購入結果は同じ。隊長の所持金にも影響しない。旧武器の維持、後から資金を得た兵士の購入、保存後の二重購入防止、各財布の実支出と個人台帳の一致も検証。

全97テスト合格（このセッションの同時実行は2以下）。Chromeは1つずつで375幅/DPR2と1280幅の表示・購入・保存を確認。ページ例外0、横はみ出しなし。v191の新規キャッシュでオフライン新遠征・廃坑の起動と描画も成功。iPhone実機は未確認。一時サーバーと確認用Chromeは停止済み。テスト生成の既存画像は実行前のバイトに復元。
