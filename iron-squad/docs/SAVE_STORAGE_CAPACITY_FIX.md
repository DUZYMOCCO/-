# セーブ容量対策 v6.11.9 / cache v259

報告は1件のセーブでも新規/上書きの両方が失敗するというもの。実機のログを取得できていないため原因は未確定。5MiB制限と大きい1枠の実データで症状を再現し、保存サイズを小さくする対策を実装した。

## 保存の扱い

- 保存枠/通常記録/地点記録の内容は変更しない。従来JSONも読める。RULES_VERSIONは5のまま。
- 128k文字以上のJSONをUTF-8/LZWで可逆圧縮。元より小さい場合だけ、encoding/chars/checksum/dataの格納用ラッパーを同じゲーム専用キーへ書き込む。
- localStorageの1回の置換が成功するまで元データを保持する。新規枠の保存先切替は書込後だけ。別枠と購入品などを削除/切り捨てしない。
- 復号サイズ/チェックサムが不正なら読込エラー。空一覧に補正して消さない。キャッシュするのは復号文字列で、公開APIが返すオブジェクトは独立。
- 書込拒否が容量不足なら「セーブに失敗しました（保存容量不足）」、権限なら「セーブに失敗しました（保存が許可されていません）」を表示。その他も失敗を表示して詳細をコンソールへ記録する。

## 確認

- 第50期・装備2500点の1枠: 地点保存約6.04MB→約0.95MB。5MiBの範囲で上書きと新規が成功。全装備/元枠/オートセーブ/地点復帰を保持。
- 圧縮後の書込も拒否される場合は保存バイトとactiveSlotIdを保持。破損した格納データを削除しない。
- 日本語/絵文字/改行/引用符/空値/辞書リセットを含む可逆往復。
- 全149テストPASS、Chromeスマホ幅/PC幅の実操作、132アセットのオフライン再起動。
- iPhone実機の原因や動作は未確認。更新後も失敗する場合は表示される理由と実機のエラー情報で切り分ける。
