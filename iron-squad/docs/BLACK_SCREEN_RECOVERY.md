# 暗転調査・描画復旧

2026-10-07 / v1.26.1 / Service Worker v83

**状態**: ユーザーから「今見たら起きなかった。とりあえずスルー」と報告があり、追加調査を停止。途中の変更はローカルに保持している。以降の兵士外見の開発で調査を再開したものではない。

## 調査結果

ユーザー端末の「フィールドが暗転してUIのみ見える」症状について、発生時の画面・ログ・開始タイミングは未取得。ブラウザ接続の一覧も空のため、実機の原因を確定したとは扱わない。

通常の48兵士・40敵の戦闘をネイティブCanvasで100フレーム描画すると、地形・部隊・敵が表示された。これだけでは開始・再開・画面変更・描画面喪失の問題を確認できないため、DOMと実画素を組み合わせたライフサイクル検証を追加した。

コード上で以下の問題を確認した。

1. 地形キャッシュは24件に制限されていたが、削除したCanvasの画像領域は明示的に解放していなかった。GCが遅れる端末では、件数制限だけでは実際のCanvas使用量を制限できない。新しいタイルを先に作るため、一時的に25件目も確保していた。
2. 画面サイズ変更時の古いビネットと、会議画面を描き直した時の古い兵士・隊長プレビューも、領域の解放をGCに任せていた。
3. Canvas描画面の喪失・復元イベントを処理していなかった。
4. 最初の更新処理が失敗すると、初回描画へ進まずCanvasが空のまま停止した。案内は短い通知で消え、エラーの原因が画面に残らなかった。この経路は例外を注入して再現・検証した。
5. フィールドの未探索マスクは不透明な黒。探索データに問題がある場面で、地形を覆う処理になっていた。

これらは修正したが、どれが今回のユーザー端末の発生原因だったかは未確定。

## 修正

- タイル生成前に最古タイルを破棄し、Canvasを1×1へ縮小して画像領域を返す。キャッシュ終了・再構築時も解放。失われたキャッシュの描画面は再生成。
- ビネットと人物プレビューの置換時、ゲーム終了時に領域を解放。
- メインCanvasをコンテナの絶対配置へ変更し、バックバッファの大きさがflexレイアウトへ影響しないようにする。コンテナとvisualViewportのサイズ変化を監視。サイズが同じなら毎回バックバッファを作り直さない。
- フレーム開始時にDPRの変換・透明度・合成方式を復元し、無効なカメラ・主人公座標と世界の範囲外の座標を補正。待機中でも補正する。描画例外でもカメラ状態を戻す。
- 新規開始・再開・サイズ変更直後は、更新処理より先に一度描画する。
- メインCanvas喪失時は進行を停止し、キャッシュを解放。復元イベントで再描画して再開する。会議や地図が開いている時は勝手に戦闘を再開しない。
- フィールドの未探索部分は半透明で陰影を付ける。全体地図・ミニマップの未探索マスクとセーブする探索記録は維持。
- 停止時は「表示を復旧」「セーブ選択」の操作と、バージョン・失敗段階・エラー本文・Canvas寸法を残す。「表示を復旧」はゲーム内容を初期化せず描画面と描画キャッシュだけを作り直す。復旧不能なら情報を残して停止する。

画素読み出しや全画面の二重バッファは本体に追加していない。人数や敵数も減らしていない。保存した遠征・装備・探索記録は削除しない。

## 検証

`iron-squad/tests/canvas-lifecycle.test.mjs` は実際の `init()`、ニューゲームのフォーム、保存した遠征の選択、会議・地図の開閉、描画ループを実行する。jsdomのCanvasを `@napi-rs/canvas` に接続し、描画された画素が黒・透明だけになっていないことを検査する。

- ニューゲーム、セーブ再開、会議・地図を閉じた後のフィールド画素。
- 昼・夜・夜明け、空の探索データ、描画状態の汚染、無効なカメラ座標、待機中に世界の範囲外にある座標、失われたビネットキャッシュ。
- 画面回転とDPR 3端末設定での描画（本体のDPR上限2を維持）。
- 初回更新へ例外を注入してもフィールドが描画され、停止案内が残ること。復旧ボタンから正常に再開すること。
- Canvas喪失・復元イベントをシミュレーションし、停止・キャッシュ解放・再開を確認。
- GCを意図的に遅延させた状態で、36タイル生成後の画像領域が24タイル分以内へ収まること。以前の削除だけの処理では画像領域が残る。
- フィールドの未探索端が、不透明な黒ではなく陰影として描かれること。

既存のUI統合テスト、性能回帰テスト、フィールド造形テストも併せて確認する。

```powershell
node iron-squad/tests/canvas-lifecycle.test.mjs <jsdomのディレクトリ> <@napi-rs/canvasを含むnode_modules>
node iron-squad/tests/interface.test.mjs
node iron-squad/tests/performance-regression.test.mjs
node iron-squad/tests/field-form.test.mjs
```

今回の環境では外部依存の位置に既定値があるため引数なしで実行できる。依存は検証用であり、ゲームに同梱しない。`CANVAS_REVIEW_DIR` を指定するとフィールド画素のPNGを出力する。

### 未確認

この検証はブラウザのスクリーンショットではない。SafariのGPU描画喪失を実際に発生させたものでもなく、端末の表示・CSS配置・PWAキャッシュの更新を実機で確認したものでもない。実機で再発した場合は、発生タイミングと「不具合の情報」の内容を確認して継続調査する。
