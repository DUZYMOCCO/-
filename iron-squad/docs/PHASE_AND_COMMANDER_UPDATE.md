# 戦線経験・120秒サイクル・新兵供給・主人公描画

2026-10-06 / v1.12.0 / Service Worker: mobile-game-studio-v31

## 戦線経験

- 生存しているだけでは戦線経験を加算しない。
- 敵・拠点への攻撃、敵からの攻撃を受けること、防御支援で今期の交戦を記録する。
- 衛生兵・大司教は実際に回復したHP量で参加を記録する。満タンの相手への空回復は対象外。
- 救助成功も実際の回復として記録する。大司教の持続回復も実回復分だけを計上する。
- 戦線が終わった時、参加した生存者だけが経験1戦線を獲得する。攻撃や回復を何度しても、1サイクルで加算する経験は1回。
- 叙勲条件・戦線生還による能力補正・死線覚醒に、参加判定を適用。主人公も同じ戦線経験ルール。
- 自費の治療・装備強化、部隊の戦果による指揮官の階級昇進は従来の処理を維持する。
- 今期の交戦・回復の記録は保存し、再開で消えたり二重に経験を得たりしないようにする。
- 名簿には「経験N戦線 / 今期参加・未参加」を表示。

## 120秒サイクル

- 戦線は75秒から120秒へ変更。新規開始は02:00表示。
- 75秒経過した時点では期を進めず、120秒経過で次期と新兵供給へ進む。
- 会議や地図を表示している間はサイクルを進めない。
- サイクルの定数と参加判定は `iron-squad/js/phase-rules.js` に分離。

## 新兵と予備兵

- 毎サイクル最低5名を受領。予備兵でも埋められない欠員が5名より多い場合は、必要数を受領する。
- 定員まで実戦部隊へ配備し、余剰は本陣の予備兵として待機する。
- 戦死による欠員や昇進による定員拡張があれば、予備兵から自動合流する。待機中の予備兵は移動・戦闘・回復・経験獲得を行わない。
- 捕虜救助で加入する兵士も、定員を超える分は予備兵へ回す。
- 再開時や再入隊時にも定員を確認し、過員は予備兵として保持する。過去に実戦を経験してから予備へ移った兵士の獲得済み経験は保持。
- HUDは「実戦 / 予備」の人数を表示。会議には前回の受領・配備数と予備兵の名簿を表示。
- 予備兵、採用番号、前回の供給記録をセーブに保存する。討死後の再入隊でも、その遠征の予備兵を引き継ぐ。

## 新兵補充が止まる不具合

既存の補充は欠員分だけだったため、定員が埋まっていると供給が0名だった。
さらに死線覚醒の分岐に未定義の `sound.playPowerUp()` 呼び出しがあり、期を進めた後に例外が発生し、新兵補充・保存まで処理が進まないケースがあった。
存在する効果音へ修正し、死線覚醒の後も補充と保存まで完了することをテストした。
旧 `completeWave()` も現行の `completePhase()` へ統一し、参加判定を迂回する処理を撤去した。

## 旧セーブ

ユーザーの明示的な削除許可に従い、今回より前のルールの遠征を整理する。
旧単一セーブ `game_studio_ironsquad_save_data_v3` と先輩バックアップ、旧形式の複数遠征を更新版で削除する。
現行ルールの遠征は `rulesVersion: 2` を持ち、以後の起動で削除しない。
整理前に新形式の一覧保存が成功することを確認し、書き込み失敗時に削除を先行しない。
実動作確認用ブラウザでは旧遠征が一覧からなくなり、現行ルールの遠征だけが残ることを確認。
端末ごとの保存領域なので、iPhone側は更新版を開いた時に整理が実行される。

## 主人公の描画

- 兵士と同じ描画モジュールを使い、甲冑の層、兜、顔、武器、盾、マント、階級章を描く。
- 主人公は兵士より少し大きく、落ち着いた名前表示と足元の目印で判別できるようにする。
- 覇王は冠とマント・鎧の色で表現。旧描画にあった発光リングや大きな光刃を追加・増強しない。
- 装備色を反映し、会議の隊長記録にも肖像を表示。
