# 走行時の短い停止対策 v6.11.10 / cache v260

報告は約3〜4秒おきの引っかかり。地形タイル512単位/通常歩行165単位毎秒で約3.1秒ごとに境界を越える。加えてv6.11.9の保存圧縮が10秒ごとのオートセーブで画面処理を止める負荷になっていた。

## 地形

- 移動方向の次の列/行だけをOffscreenCanvasのWorkerで準備。完成画像とオブジェクト/キャンプ情報を受け取り、従来のキャッシュへ配置する。
- 同じgenerateを使うので地形/RNG/座標/衝突は同じ。Chromeの従来画像とのピクセル差0、オブジェクトとキャンプも一致。
- 先読みは表示中のタイルを追い出さない。待機8件以下、主キャッシュ24MiB。転送画像は貼り付け後/不要時にcloseし、clearでWorkerも終了する。
- 未表示の先読みキャンプは補給/危険地帯の安全判定に使わず、商人の発見は従来のvisibleCampsだけ。Worker非対応/失敗は従来描画を使用する。

## 自動保存

- 更新周期10秒はそのまま。保存一覧の復号/結合/JSON/圧縮を別Workerへ移す。画面側には現時点のスナップショットの複製と、最後の原子的localStorage書込が残る。
- 世代番号と元の保存バイトを照合し、新しい保存/手動保存/別枠作成/削除/別タブの書込後に古い背景結果を適用しない。
- 画面非表示/手動/地点セーブは同期保存を維持。保存形式/地点記録/旧記録/失敗時の原状保持はv6.11.9のまま。Worker不可時は互換保存する。

## 計測と限界

Chrome390×844、CPU4倍の使い捨てデータで計測。

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| 自動保存が走る更新フレーム | 342.4ms | 30.1ms |
| 260フレーム歩行中の地形描画最大 | 42.3ms | 2.6ms |
| 同期地形生成の回数 | 4 | 0 |

背景保存中も実ゲームループで隊長が33単位移動し、保存は完了した。全153テストと134アセットのオフライン起動/両Workerの動作を確認。

初回地形作成/その他の描画コストやiPhone実機の体感まで解消したとは言わない。元のiPhoneのトレースは未取得。性能計測の最初の再実行は起動待ち30秒で失敗したが、全件テスト終了後の再実行は成功。
