## 再現できた不整合

P2は次の仕上げで優先する不整合、P3は表示や自然さの改善。今回の範囲で、進行不能やセーブ破損に相当するP0/P1は確認しなかった。

### F1 / P2：酒場の戻り先と軍資金の表示

フィールドの入口から酒場に入り、閉じると、司令部のランチャーが残る。`inBattle=false`、`dialog-open=true` のままで、さらに「戦場へ戻る」を押すまで歩行を再開できない。工房やカジノは一度の閉じる操作でフィールドへ戻るため、施設の動作が揃っていない。

同じ終了処理で所持金も古い表示になる。入場前1,000G→雇用で200G支出→実際は800Gだが、戻ったランチャーの軍資金は1,000Gだった。保存された金額を失うバグではなく表示の不整合。

- [酒場の出口処理](../js/tavern.js#L98)：`openStrategyModal(true)` で下の画面を開くが、閉じる際は酒場だけを除去し、戦況画面の更新/復帰をしない。
- [軍資金の描画](../js/index.js#L9706) は `renderStrategyUI()` で更新。酒場の雇用後は `updateStatsUI()` と `renderTavern()` のみ。
- [酒場を閉じた画面](previews/full-audit-20261012/09-tavern-exit.png) / [実際の支出後の古い表示](previews/full-audit-20261012/31-stale-tavern-funds.png)
- 修正方針：入場元を保持し、フィールドから入った場合は直接フィールドへ、メニューからの場合は元の画面へ戻す。戻る前に取引後の表示を更新する。

### F2 / P2：「今は旅を続ける」でも歩行が再開しない

勧誘イベントで「今は旅を続ける」を選ぶと、勧誘の画面は閉じるが司令部が残り、時計と移動は停止したまま。選択肢の意味と終了後の動作が合わない。加入の強制や仲間の喪失はなく、手動で司令部を閉じれば旅を続けられる。

- [勧誘の開閉](../js/index.js#L8187) はF1と同じ画面の重ね方。
- [保留直後](previews/full-audit-20261012/15-decline.png) の状態は `career=invited / inBattle=false / strategyVisible=true`。
- 修正方針：保留時は、勧誘前の探索へ戻す。加入時は軍の案内を表示するなど、選択後の目的に合わせる。

### F3 / P2：外郭が完成しても移動中の商隊が旧経路で壁を抜ける

Lv2時点の経路を持った商隊が、Lv3で外郭が完成した後も保存している `points` を使う。交易路一覧の経路を門へ通る形に更新しても、この商隊は更新前の線を使う。

制御した再現では、東門の開口から外れた東+800・南+400の壁を、東+700→東+908へ1秒で通り抜けた。完成前は通行可能、完成後の同じ線は城壁の遮蔽判定で遮られることを確認した。引き継ぎに記載された既知の未対応点を再現できた。

- [経路更新](../js/trade-routes.js#L40) / [商隊が自分の旧pointsを優先](../js/trade-routes.js#L162) / [移動時の座標設定](../js/trade-routes.js#L169)
- [再現画像](previews/full-audit-20261012/29-traffic-through-outer-wall.png)
- 修正方針：外郭/経路の更新時に移動中の一行も道を引き直す。現在地を急に飛ばさず、門への接続を探し、見つかるまで停止する。護衛も商隊と同じ経路へ移す。

### F4 / P2：開始画面に軍人開始の説明が残る

新規遠征の説明が「新しい部隊で出発」「第1期・新兵48名・部隊回復薬1個から開始」のまま。一方、実際の主人公は在野の旅人で、同行者は0人から、仲間の上限は5人。本隊48名は自分が指揮できる部隊ではない。

- [開始説明](../js/index.js#L1825) / [実際の旅人開始](../js/index.js#L2365)
- [開始画面](previews/full-audit-20261012/01-save-menu.png)
- 修正方針：「旅人として出発、酒場で仲間を探す、仲間5人まで、本陣への加入は任意」を最初に伝える。本隊48名は本陣の独立した軍として説明する。

### F5 / P3：初回起動直後のオフラインでカードの版表示が空になる

新しいChromeプロファイルで起動・ゲーム開始・キャッシュ完成後、通信を切ってハブを再読込すると、`iron-squad/sw-assets.js` がService Workerから503になり、ゲームカードの `v6.0.0` 表示が空になった。同じ取得方法の他ゲームの版情報にも503が出る。IRON SQUADの保存した遠征の再開は成功しており、ゲーム本体のオフライン起動を阻害する問題ではない。

- [URLと応答・再開結果](previews/full-audit-20261012/offline-probe.json)
- 原因の範囲は共有ハブ/SW側の版情報のキャッシュ。共有ファイルは今回変更していない。
- 修正方針：初回取得時に版情報を保存するか、オフラインでは最後に取得できた表示を保つ。

### F6 / P3：主人公と同行兵で施設の通行判定が違う

主人公は建物の前面を通れないが、普通の軽装兵は通れる。実際の同行AIでも、工房の南側から北側の主人公へ追従する間、建物内を11フレーム通過した。移動は止まらないが、建物との重なりや屋根の下で見失う動作につながる。

- [主人公だけに追加した判定](../js/index.js#L6949)
- 戦闘バランスを保つために分けた既存の実装上の選択。単に全員を止めるだけでは本陣防衛や救助の経路を壊すため、同行兵には回り道を用意する必要がある。攻撃の遮蔽と歩行の経路は分けて扱う。
- 再現した `LIGHT` は上位職の壁通過能力を持たない。詳細座標は追加再現JSONの `follower`。

## 演出と細部を強める順番

### 1. 魔王討伐の区切り

討伐フラグ、宝箱の解錠、報酬、日誌/戦況の記録は保存される。一方、画面上は通常のボス撃破に近く、文字の報酬が重なり、討伐後も戦闘状態のまま。[討伐直後](previews/full-audit-20261012/26-demon-victory.png) / [保存される記録](previews/full-audit-20261012/27-victory-record.png)。

`hero-party.js` の `recordDemonKingDefeat` と `index.js` の魔王撃破処理に、短い区切りを足す効果が大きい。数秒の静寂、勇者または仲間の一言、「誰が討伐したか・同行者の生存・今回の旅」の振り返り、帰還/旅の継続の選択を提案する。強制入隊や強制終了にせず、在野での達成も認める。ゲームを続ける場合は残党との戦いとして言葉を変えると世界の変化が伝わる。

### 2. 旅人の導入と酒場の人物

開始後の本陣は兵が多く、工房/組合は営業準備中。最初に「今は一人旅・仲間は酒場で会う」を短く示すと目的が明確になる。酒場の3段階の会話と信頼の機能は成立しているが、全員が同じ質問を使う。兵種/人物ごとの自己紹介や、加入時・待機時の一言を少し変えると、成長して保存される仲間への愛着につながる。

### 3. 勧誘・外郭完成・勇者出現を場面として見せる

勧誘には任意の選択と軍服への変化が実装済み。使者や出迎え、仲間の反応があると功績の意味が伝わる。外郭完成も、短い門の開通案内と門番の一言があれば地形の変化を見落としにくい。

勇者は第10期から各期2%で出現し、現状の案内は確率/成長20倍/各員の能力が主体。出現前の噂、天啓直後の目的、城への出発時の会話を足し、数値は詳細へ置くことを提案する。希少さを変える判断とは分ける。

### 4. 近場の案内

地図は街道・地形・拠点の案内が主体で、外郭の形と門の位置、本陣内の施設の区画は表示しない。近場の地図で門と施設の目印を示すと、メニューを経由しない施設の設計と揃う。世界全体にすべての小施設名を並べる必要はない。
