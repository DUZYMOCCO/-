## 1. セーブ書込み前の読み戻し検証（優先・データ保護）
- 現状: `js/save-codec.js` の `encodeSaveList` は圧縮結果を検証せずに返す。全スロットが1キー（`ironsquad_save_slots_v1`）なので、コーデックの不具合があれば良いセーブを壊れたデータで上書きし、全スロットを失う。
- 修正: 圧縮した場合は `unpackSave` で解凍し、元の json と完全一致することを確かめてから返す。不一致・例外なら圧縮をやめて生の json を返す（または例外にして書込みを中止し、既存データを残す）。どちらを選んだかと理由を結果に書く。
- オートセーブではワーカー内で走るので、コストは許容。メインスレッドの同期保存（`writeSlots`）でも同じ検証を通す。
- テスト: 正常往復、検証失敗時に既存の localStorage が変わらないこと。

## 2. ワーカー内エラー時の救済（`js/save-slots.js` の `completeJob` / `onmessage`）
- 現状: ワーカーそのものが落ちた（`onerror`）ときはメインで再実行するが、ワーカーが `{error}` を返した場合は `failed` で終わる。`workerDisabled` にもならず、10秒ごとのオートセーブで同じ失敗を繰り返す。
- 修正: `data.error` を受けたら、その job が最新（`job.revision===revision`）ならメインスレッドの同期保存で1回やり直す。連続して失敗したらワーカーを無効化してメイン保存に切り替える。
- 既存の supersede 判定（古いスナップショットで新しい保存を上書きしない）は崩さないこと。
- テスト: ワーカーがエラーを返す → メインで保存される／古い job は書かない。

## 3. 遠征中に戦死した予備兵がロード後に残る（`js/index.js` 3530行付近）
- 現状: 帰還処理（2700行付近）は死亡した予備兵を `reserves` から除くが、ロード時の掃除は `clearReserveExpedition` を呼ぶだけ。帰還前にセーブ→再開すると、死亡兵が `reserves` に残り「予備N名」の表示（5460/5477行など）が多くなる。
- 修正: ロード時の掃除でも死亡兵を `reserves` から除く（帰還時と同じ扱い）。
- テスト: 遠征中に予備兵が死亡 → 保存 → 読込 → `reserves` に残らない。

## 4. 指揮官にも装備バリアを効かせる（`js/defense-equipment.js:50`）
- 仕様（ユーザー決定）: 指揮官は魔法も使えるので、術士装備のバリアが効くようにする。
- 現状: `canUseEquipmentBarrier` は `isMage(unit)` と衛生系の `soldierClass` のみ。指揮官（attributeFamily COMMANDER）は対象外になり、バリアが 0/0。
- 修正: 指揮官（プレイヤー本人）も対象に入れる。`magic-rules.js` の `isPlayerCaster` などの既存の判定があればそれを使う。筋肉魔法使いや非術士職の兵士は今までどおり対象外。
- ついでに、衛生系の判定が `soldierClass` だけを見ていて `combatClass` を見ていない点を `isMage` とそろえる。
- ステータス画面のバリア表示と、装備説明文の「魔法使い・衛生術師のみ有効」を実際の条件に合わせる。
- テスト: 指揮官がバリア付き装備 → `equipmentBarrierMax>0`。非術士の兵士は 0 のまま。

## 5. ロード画面でセーブ枠を見分けやすくする（`js/index.js` の `showSaveMenu`、1900〜1950行付近）
- ユーザーの声: 「セーブ名だけだと区別がつかない」。地点セーブの「新しいセーブデータとして保存」で `元の名前 · 日時` の枠が増えるので、一覧で見分けられない。
- 保存の仕組みは変えない（上書きは今のまま、通常記録と地点記録の両方を置き換えてよい）。表示だけを直す。
- 各カードで、少なくとも次がひと目で分かるようにする:
  - 通常記録（オートセーブ）と地点記録を、それぞれ「場所・第N期・日時」で別の行に分けて表示する。今は通常記録に場所がない。通常記録の場所はスナップショットから出す（既存の地名関数を流用）。
  - 隊長の名前と Lv。
  - 今プレイ中の枠（`activeSlotId`）の印。
- 名前が長くなりすぎないようにする（`元の名前 · 日時` を何度もコピーすると崩れる）。日時は名前に入れず、表示側の日時行に任せる形を推奨。
- 390×844 のスマホ幅で崩れないこと。スクリーンショットを `docs/previews/` 以外の作業用フォルダに残し、結果に場所を書く。
