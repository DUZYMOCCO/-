## 2026-10-18 / 2.7.0 / cache v10

依頼: ステージと高難度の追加、アリが食べる音を柔らかく控えめに変更。追加指示: 手詰まり時に「あきらめる」も追加。

### 変更

- `pictures.js` に12種類追加、全18種類。元の1〜6面は維持し、7面から新しい絵へ進む。保存済みステージ番号は維持する。
- 7〜12面: ドーナツ、アイス、ペンギン、さくら、きつね、ロケット。13〜18面: 宝箱、ふくろう、蝶、キャンディ迷宮、クリスタル、お城。
- 13面以降は上級。出撃3枠、先頭以外は伏せ、内側色の連続を最大4枚、鍵3組。25面以降は超上級で最大5枚・鍵4組。既存の解法生成と外郭制約は継続。
- `soft-audio.js` を追加。0.14秒の丸い波形を1度だけPCMへ生成し、共有SoundEngineに固有名で登録。低めの周波数、緩やかな立ち上がり・減衰、控えめな振幅と音量。0.18秒の間隔制限で音を重ねない。
- 食べるイベントの `hit` 呼出しだけを専用音に変更。共有音声ファイルは編集せず、共通ミュート・非表示・効果音音量へ従う。やり直し・退出時はこのゲームの食事音だけを停止。
- STUCKに「あきらめる（工房へ）」を追加。destroy後に工房へ戻り、保存された進行を変更しない。小さい画面でダイアログが収まるよう高さ制限とスクロールを設定。
- ゲーム内モジュール参照とSW一覧を更新。共有ファイル、他ゲーム、既存の未コミット変更は保持。

### 検証

- `node --test color-ants/tests/*.test.mjs`: 20件成功。全18種×2周=36面の解法を通常速度と倍速で再生。パレット・総数・鍵取得順・列の先頭へのアクセスを検証。
- 新しい上級6面すべてで、内側色を3枠に抱えた実際の手詰まりを再現。解ける配置と誤選択による詰みの両方を維持。
- 食事PCM: 44.1/48kHzで有限・控えめなピーク・滑らかな端点と隣接サンプル差・高周波成分の抑制を検証。キャッシュ再利用、音の非重複、ミュート・非表示・効果音0、他グループを止めない退出を検証。
- `COLOR_ANTS_ORIGIN=http://127.0.0.1:8001 node color-ants/tools/playtest.mjs`: Chrome / DPR2。5画面サイズ、18種類の実画面を撮影し、一覧を目視確認。
- ゲーム本体で1〜36面を列先頭の通常操作・道具なしで全回収（時計のみ早送り、進捗値の注入なし）。
- 実際のAudioContextと共有ミキサーを通じて専用音の呼出し・バッファ・ミュートを確認。計測値は report.json の audio。物理スピーカーやiPhone実機での聴感評価はしていない。
- 37面で実際にSTUCKにして「あきらめる」を押し、ループ停止・工房復帰・保存値不変を確認。再入場が同じ37面であることを確認。

## 2026-10-16 / 2.6.0 / cache v9

依頼: 面白いが手詰まりが起きないため、難易度を上げる。

### 調整

- `difficultyFor(level)` で段階的な難度を管理。1〜6面は4枠・もどす2回、7面以降は3枠・もどす1回。
- 枠+1・シャッフル・そうじは各面1回。待機枠のタップも「もどす」と同じ残数を消費し、無制限返却を廃止。もどすは最後に入れた返却可能なタイルを選ぶ。
- 早期の内側色を最大3列へ置き、4面以降は最大4列。1列に最大2枚、7面以降は最大3枚を続ける。先に同じ待機色を複数抱える判断が手詰まりにつながる。
- ただし各列の途中へ必要な外郭色を埋めない構成は維持。解法と鍵の取得順を残す。
- 4面以降は奥の2段を「？」にする。回数バッジ、手詰まり画面の残数・枠追加を追加。救済しても詰み状態が解消していなければダイアログを閉じない。
- やり直しは盤面と回数を初期化。既存の進行保存キーは継続。変更は `color-ants/` のみ。

### 検証

- `node --test color-ants/tests/*.test.mjs`: 16件成功。18面の通常・倍速の解法を新しい4枠/3枠で再生。
- 間違った選び方の検証: 1〜12面で、まだ露出していない色を優先して枠へ入れると10面で開始時点の手詰まりを再現。これは意図した誤選択シナリオの検証で、ランダムプレイの失敗率ではない。きのこ2面は開始時の内側色が少なく、この手順では満枠に至らない。
- `node color-ants/tools/playtest.mjs`: Chrome / DPR2、5画面サイズ。通常の列先頭タップで1面・7面のSTUCKを発生させ、戻す2回を使い切り、待機タップでも制限を迂回できないこと、枠追加で空きができること、再挑戦で回数が戻ることを確認。
- そうじ・シャッフルは2回目を直接呼んでも盤面を変更しない。そうじ後の残数保存則も成功。
- 実際のゲーム本体で1〜12面を通常の列タイル操作、道具なしで全回収。1〜6面は4枠、7〜12面は3枠。回収値の注入はせず、シミュレーション時間のみ早送り。
- JavaScript構文検査・差分の空白検査。スクリーンショットで初期画面、実手詰まり、返却回数枯渇、3枠の手詰まりを目視確認。

証跡: [検証レポート](validation/v2.6.0/report.json)、[手詰まり](validation/v2.6.0/stuck.png)、[もどす枯渇](validation/v2.6.0/undo-exhausted.png)、[3枠](validation/v2.6.0/hard-stuck.png)。

ローカル検証URLは `http://127.0.0.1:8001`（`COLOR_ANTS_ORIGIN`）。iPhone実機Safari/PWAの操作感・難度評価は未確認。

## 2026-10-15 / 2.5.0 / cache v8

ユーザーの修正指示: アリが自分の色へ直接進む状態を直し、外郭から削っていく順番と5枠のやりくりをパズルの中心にする。

### 修正

- `perimeter.js` を追加。盤面を一周できる余白から、4方向で外部とつながる空間を探索。閉じた背景・内部空洞・斜め接続は外部と見なさない。
- `colony.js` の露出判定、標的予約、手詰まり、そうじを同じ外郭判定に統一。標的へ一直線に進まず、空いている通路をたどって外郭へ進み、来た経路を戻る。画面サイズ変更時もアリの盤面内位置を保つ。
- `puzzle.js` は外郭から回収できる同色領域を順に取り除く手順からタイルを生成。必要なタイルが、未来の色の後ろに埋まらないように列へ配置する。
- 内側の色を早めに見せる選択肢を最大2列へ配置。正しい順番なら道具なしで進めるが、先に内側の色を抱えすぎると枠を圧迫する。ゲーム中に色を無視して救済回収する仕組みは加えていない。
- 鍵とロックを対応付け、解法中で鍵が先になるように配置。シャッフルも必要な順序を壊さず列を振り直す。
- そうじの回収数は、同色の複数枠と列の残数へ正確に割り当てる。消えた鍵タイルも対応ロックを解除する。
- 画面下の案内を「外郭の色から食べよう・内側の色は待機」に更新。描画するアリの大きさ・横ずれを盤面内ではマス幅へ収める。
- ゲームのみ v2.5.0 / cache v8。新モジュールをキャッシュ一覧に追加。共有ファイルは変更していない。

### 検証

- `node --test color-ants/tests/*.test.mjs`: 15件成功。
- 回帰テスト: 閉じた空洞、斜めの隙間、外側に接続後の開通、内側の色の待機→自動再出撃、別色を横切らない往復、リサイズ、そうじの数の割当て。
- 6種×3周の18ステージについて、実際の出撃・往復・回収シミュレーションを使い、通常速度と倍速・異なるフレーム間隔・巣穴の距離で解法を再生。鍵取得順、各手の列先頭へのアクセス、盤面全回収まで確認。
- `node color-ants/tools/playtest.mjs`: ローカルChrome / DPR 2。5画面サイズ、全6種の表示、主要操作、そうじ後の残数保存則を確認。ページ/HTTPエラーなし。
- ブラウザー内のゲーム本体でも全6種を5枠・道具なし・列先頭の通常操作で完走。シミュレーションの時計は早送りし、回収数を注入せず、実際の回収が全数に達したことを確認。
- 構文検査と `git diff --check -- color-ants/`。

証跡: [検証レポート](validation/v2.5.0/report.json)、[外郭待ちと出撃中](validation/v2.5.0/playing.png)、[全回収後のクリア](validation/v2.5.0/real-clear-1.png)。ほか5種の実クリアも同フォルダに保存。

制約: iPhone実機Safari/PWAの操作感・速度・更新反映は未検証。解法があることと、どの手順で選んでも詰まらないことは区別する。5枠を内側の色で埋める手詰まりは意図したゲーム性として継続。
