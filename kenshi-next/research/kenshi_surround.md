## 3. 本作で仲間が敵に密着して殺到する理由（コードで確認）

1. **待つ輪が近すぎる**: `ai.js` の `WAIT_RING_EXTRA = 1.2`。待つ半径は「自分の武器の間合い + 1.2m」。打ち込む人は間合いの0.8倍に立つので、待つ人は **打ち込む人の約1.5m後ろ** に立つだけになり、ほぼ密着して見える。
2. **角度を割り当てていない**: `strafe()` は「今いる角度」から ±0.025rad/tick 回るだけ。仲間はふつう同じ方向から来るので、**同じ側に固まる**。重なりを解くのは押し合い（衝突）だけ。
3. **クロスボウの人も近接の枠を使う**: `countTargeters()` は狙っている人を全員数える（飛び道具かどうかは見ない）。そのため
   - 撃っている人が近接の枠を埋め、剣の仲間は「待つ」に回される。
   - 枠が取れなかったクロスボウの人は `waitTargetId` を持ち、**近接の待つ輪（間合い+1.2m）まで歩いて行く**。今は「みんなクロスボウを持っている」ので、撃つべき人まで敵のそばに集まる。
4. **歩いて向かっている人も枠を取る**: `countTargeters()` は遠くからまだ歩いている人も数える。遠い人が枠を持ち、近くの人は待つ、ということが起こる。`trimAttackSlots()` も配列の順番で切るので、距離は見ていない。
5. **枠が空いた瞬間に全員が反応する**: `claimWaitSlots()` は枠が空いたらすぐ入れる。`detectEnemies()` は5tickごとに一番近い「埋まった相手」を選び直す。そのため、空いた枠に待つ人が **すぐ走り込み**、出入りがせわしなく見える。
6. **枠は 2**（`data.js` の `ATTACK_SLOT_LIMIT = 2`）。Kenshi のバニラ（1）より多く、相手が打ち込み中・ひるみ中でも減らない。

## 4. 直し方の案（このタスクでは実装しない）

★ の数値は本作で試すための仮の値。Kenshi の値ではない。

1. **枠は「届く距離にいる人」だけで数える**: 間合い+1m 以内の人だけで数え、遠くから歩いてくる人は枠を取らない。trim も距離の近い順にする。
2. **飛び道具は近接の枠と分ける**: クロスボウ・投げ物の人は `countTargeters` に入れず、待つ輪にも入れない。射程の0.6〜0.85倍★で、味方の近接の後ろ・横に立つ（今ある `keepDist` を使う）。
3. **待つ輪を広げる**: 半径を「間合い + 2.5〜3.5m★」にする。打ち込む人の後ろに隙間ができる。
4. **角度を割り当てる**: 相手ごとに、待つ人を id 順に並べて 360°/人数 で割り当てる（打ち込む人の角度は空けておく）。割り当てた角度に向かって回り、その近くで小さく揺れる（同じ側に固まらない）。
5. **入るまでの間**: 枠が空いても 0.5〜1.5秒★ 待ち、割り当てた角度に一番近い人だけ入る（全員が一斉に走り込まない）。
6. **枠の数**: 人型の相手は 1〜2★（相手が打ち込み中・ひるみ中は 1）にし、大型の動物には追加枠を持たせる。Kenshi の「1」はプレイヤーに不評なので、2 のままで 1〜5 の案を試すのもよい。
7. **テスト案**: 仲間6人 対 敵1人で、①待つ人どうしの距離が1.5m★以上、②待つ人と敵の距離が「間合い+2m★」以上、③クロスボウの人が射程の0.5倍★より近づかない、を確かめる。
