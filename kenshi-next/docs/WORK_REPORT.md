## 2026-11-07 フリーズ（パイルドライバー再生時の無限ループ）を直した（v22 / 0.14.2）

試合開始から約125〜150秒で固まる問題の根本原因を特定し、修正した。

原因:
- martial2_male.json の新しい Pile Driver A/B は、GLB 変換のため
  トラック固有の times（個別のキーフレーム時刻）を持っていた（各トラック 195本）
- 一方、decodeMartialPack() はトラック固有の times を使わず、
  クリップ共通の85個の時刻を使っていた
- 例えば root.position は値が6個（2キーフレーム ×3成分）しかないのに
  85時刻が与えられ、Three.js が「1時刻あたり 6/85 値」と整数でない解釈に
  なり、補間処理が終了できなくなって無限ループに入る
- 該当技（Pile Driver）が選ばれたタイミングでフリーズするので、発生時刻は変動した

修正（js/render/martial_pack.js）:
- decodeMartialPack() で、トラック固有の times があればそれを優先し、
  無い従来データにはクリップ共通の times にフォールバックするようにした
- 値の数と時刻の数が一致しないトラックは検出してスキップする
  （再生前に不正を弾き、フリーズを防ぐ）

回帰テスト（tests/martial_pack.test.mjs）を追加。実データで全トラックの
一致を検証する。node --test kenshi-next/tests/*.test.mjs → 31件 通過。

版（AGENTS.md §2）: sw-assets.js の version v21 → v22、gameVersion 0.14.1 → 0.14.2（不具合修正なのでパッチ）。

コミット 072eb5af、push 済み。公開サイトは v22 / 0.14.2。

※ 別件として combat_fx.js:176 で、人物が消えた後も気絶表示用の描画物が

## 2026-11-05 受けの予告を振りかぶり全体にした（戦闘が読みやすくなるように v0.3.1）

### 測ったこと
ヘッドレス決闘（1v1 / 3v3 を 150 秒回し、振り始めに対する結果を数えた）:
- 当たる 約65%、**受けられる（ダメージなし）約31〜48%**、かわされる 約3%、射程外で外れる 約0%
- つまり「ノーダメージでスルー」の主因は射程ではなく受け。`blockBase: 70`（同格なら7割受ける設計）で、
  受けられるのが 3〜5 回に 1 回が当たり前になっていた
- 受けの構え（手続きポーズ）は、当たる瞬間（impact）から 0.3 秒しか半分まで上がらなかったので、
  振りかぶりの間は受け手が何も構えていないように見え、刃が相手を「通り抜ける」ように読めた

1. 「パワーボムなのかな 小手投げみたいにみえるけど。これはこれでいい」→ **次項のとおり、担ぎ上げを入れてパワーボム寄りにした**
2. 「なんか投げ技で死亡するとTポーズになってる」
3. 「やっぱり気絶したキャラに追撃はすぐ相手が死ぬからやめる」
4. 「移動している相手に暗殺しようとするとカクカクする。相手が歩いてるせいで目標がおかしくなっているのかな」

### 直したもの

**1. パワーボムらしくした（`js/data/martial_moves.js`）**

調べたパワーボムの形（前屈みの相手に両腕を回してクラッチ → 反動で担ぎ上げ → 頭から背中にかけて叩きつけ）に合わせ、
`playFrom` を 4.6 → **3.2** に戻して**組み付き〜担ぎ上げ**が入るようにした。
当たりは発生から **2.73秒**、全体 **4.37秒**（前は 1.50秒／3.30秒で落下だけが見えていた）。
※ `EndPose` 等の値はクリップの実データのままで、値の作り直しはしていない。

**参考（パワーボムとは。ネットで調べた一般的な説明のまとめ）**
- 基本の3段階: (1) 前屈みの相手に両腕を回して胴をクラッチ、(2) 反動で相手を担ぎ上げる（肩の高さ〜頭上）、
  (3) 後頭部〜背中から叩きつける。叩きつけた後に押さえ込む型と、投げっ放しの型がある。
- バリエーション: 高角度（頭上まで担ぐ＝ラストライド系）／シットダウン（自分も尻餅をついて落差を足す）／
  投げっ放し／ジャンピング式 など。**高く担ぐほど映える**とされている。
- この世界の「Hell Slammer」は、担ぎ上げ→逆さにして頭から落とす形なので **高角度寄り**。
  「もっとパワーボムらしく」と言われたら、`playFrom` をさらに前に戻して担ぎ上げを長く見せるのが第一手（土台のアニメは変えない）。

**2. 投げで死んだ時のTポーズ（`assets/anims/martial2_*.json`）**

原因は**採用した Hell Slammer の pack metadata に `endPose` が無かった**こと。
描画（`dolls.js` の `playAction`）は `clip.userData.endPose != null` の時だけ `clampWhenFinished` を立てる＝
「最後のコマで止めて保持する」ので、`endPose` が無いとクリップが最後まで行った瞬間に重みが 0 になり、
**人形を作り直した時（遠くへ行って戻った・再読込）に姿勢が消えてTポーズ**になっていた。

- 実測（人形を作り直した時の状態）: 直す前 `weight 0 / enabled false`（Tポーズ）→ 直した後 `weight 1 / paused / clamp true`
- 他の採用済みクリップ（Shoulder Throw, Victim / Double Leg Takedown - Victim）は元から `endPose` を持っている。
  同じ形にそろえた（`Hell Slammer A`: `standing`、`Hell Slammer B`: `prone`）

**3. 気絶した相手への追撃をやめた（`js/sim/ai.js` / `js/sim/combat.js`）**

v0.6.0 で「命令で狙った相手なら、意識を失って倒れても追う（とどめまで）」にしたが、**すぐ死んでしまう**ため戻した。
戻した場所は4か所（`ai.js` の `dropDown` と視界の敵の走査、`combat.js` の攻撃開始判定と `resolveStrike`）。
**投げで転んだだけの相手（意識あり＝`knocked`）への追撃は今までどおり**。

**4. 歩いている相手への暗殺が詰められない／カクカクする（`js/sim/stealth.js`）**

- 相手の 1tick の移動を見て、**0.3秒ぶん先**を狙う（毎tick ゴールが「いまの相手の真後ろ」に跳ぶのを防ぐ）
- 回り込みの切り替えに**幅**を持たせた（110度で回り込み開始・130度で背後とみなす）。境目で出入りすると
  狙う点が 1.0m と 1.25m の間で跳んで、その場で震えて見えた
- 歩いている相手（1.6m/秒）には**同じ速さだと永久に詰められない**ので、寄る時は 1.9m/秒（小走り）

実測（6m の円を 1.6m/秒で歩き続ける相手、1800刻まで）:

| | 歩いた距離 | 最短距離 | 暗殺 |
|---|---|---|---|
| 直す前 | 277.6m | 4.00m（詰められず） | **未成立**（止まり↔動き出し 3回） |
| 直した後 | 121.5m | 1.09m | **688刻で成立**（止まり↔動き出し 2回） |

- リポジトリ内テスト 29件 通過（`tests/assassination-approach.test.mjs` 4件を含む）
- ハーネス1116件は HEAD 比で新たな失敗なし

## 2026-11-05 攻撃命令は倒れても追う・強い打撃で気絶した相手が何十分も寝たままになるのを直した（v8 / 0.6.0）

### なぜ（佳之さんの指摘）

1. 「敵を『攻撃する』にして、その相手をノックアウトすると、その指令を出したときの位置に戻ろうとする」
2. 「まだ転倒した相手をスルーしてしまう挙動が残ってる」
3. 「敵のダウンと自然回復の仕組みだけど、自然回復もしないけど死ぬわけでもないのが結構いる、ずーーと寝てる感じ」
4. 「kenshiと同じならば傷を手当てしない状態を放置すると傷が悪化して減少が回復力を上回っていずれ死に至る」

### 直したもの

**命令で攻撃した相手は、倒れても手を離さない（`js/sim/ai.js` / `js/sim/combat.js`）**

命令（`orderedTargetId`）で狙っている相手は、意識を失って倒れても狙いを外さず、とどめまで追う。
そのため戦いが終わったとみなして持ち場へ戻ることもなくなる。

- ai.js: 倒れた相手を外す判定（`dropDown`）に `orderedHere`（＝その相手が命令の相手）を追加
- ai.js: 相手を探す所（視界の敵の走査）でも、命令の相手は倒れていても候補から外さない
- combat.js: 攻撃を始める判定と、当たり判定（`resolveStrike`）でも同じ除外
- **命令が無い相手は従来どおり**（意識を失った相手は斬らず、狙いも外す。`DOWNED_HARM.attack=false` はそのまま）

**強い打撃で気絶した相手が何十分も寝たままになるのを直した（`js/sim/body.js`）**

気絶中に抜ける「気絶（stun）」の速さが、自然回復と同じ 1秒 0.0125 になっていた（最大100の部位）。
打撃で stun が 120〜150 溜まった相手は、**12.7分〜31.8分** その場に倒れたままだった（死にもしない）。
休んだ時の速さ（1秒 0.5）にした。KO の長さ（`koTicks`）どおり 1分以内に起き上がる。

**体力（hp）の自然回復は入れない**。調べたところハーネスに「倒れた相手の手当てしていない傷は自然回復しない（rc1 規則）」という
テストがあり、**そちらが正しい**（佳之さんの 4 のとおり Kenshi も手当てが要る）。
手当てしないまま放置すると感染（`fester`）で傷が悪化し、いずれ死に至る——この動きは元からあった（下表で確認）。

### どう確かめたか（実測）

気絶の抜け（胸 hp100・傷なし・KO 24秒。1体を60分観察）:

| 胸の stun | 直す前 | 直した後 |
|---|---|---|
| 60 | 0.2分で起きた | 0.2分で起きた |
| 120 | **12.7分で起きた** | 0.4分で起きた |
| 150 | **31.8分で起きた** | 0.8分で起きた |
| 200 | 即死（hp−stun が −最大以下） | 即死（同じ） |

倒れてから20分の結果（種族3×体力4×stun4＝48通り）: 起き上がった 18 / 死亡 30 / **倒れたまま 0**（直す前は 12 / 36 / 0）。
「倒れたまま残る」は出ず、必ず「起きる」か「死ぬ」に落ちる。

命令の攻撃（仲間1人が武器を持って相手を60秒殴り続けた結果）:

| 相手の状態 | 直す前 | 直した後 |
|---|---|---|
| 立っている | 命中16・700→663 | 同左 |
| 転倒（意識あり） | 命中28・700→502 | 同左 |
| 気絶(KO)・**命令あり** | **命中0・狙いを外す** | **命中28・700→502・狙いを保持** |
| 気絶(KO)・命令なし | 命中0・狙いを外す | 同左（従来どおり） |

- テスト: リポジトリ内 29件 通過。ハーネス全件（1116件）は HEAD 比で新たな失敗なし
- 確認したハーネス: `knockdown` / `rescue_bed` / `needs` / `coma` / `death` / `throwdown_recovery` / `ma_rest1` / `town_food`

## 2026-11-05 気絶の倒れ方（スケキヨ）・同じ敵への殺到・投げた後の追撃（v5 / 0.4.0）

### なぜ（佳之さんの指摘）

1. 「ノックアウトされた敵がみんなスケキヨみたいになってる」
2. 「間合いを取るって設定した気がするんだけど生きてないな、みんな同じ敵に殺到して密着する」
3. 「格闘で転ばせた後終わった扱いでターゲットはずれてしまうのも直ってない」

### 原因と直し方

**1. スケキヨ（`js/render/dolls.js` / `js/render/ko_collapse.js`）**

2つ原因があった。

- **二重に寝かせていた**: ラグドールが姿勢を地面に伏せたあと、`dolls.js` が
  「倒れクリップが無い時」用に `root.rotation.x = -π/2` でさらに寝かせていた。
  KO は `customDown` が false になったのでこの処理が当たり、**体がもう90°回って脚が上を向いていた**
  （実測: 地面から 足 6.98 / 骨盤 6.21 / 頭 5.59 = 脚が一番高い）。→ ラグドールが居る時は寝かせない
- **全員が同じ姿勢に収束していた**: 倒れ終わりに「Fall クリップの最終フレーム」へブレンドするので、
  経過が違っても最後は全員同じ格好になる。→ 手足（腕・脚）だけ人ごとに ±0.4rad（±23°）ずらす
  （胴＝背骨・首・頭は揃えたままなので、起き上がりの繋がりは崩れない）

**2. 同じ敵への殺到（`js/sim/ai.js`）**

`surround.js` の待ち輪は**自動で狙いを付けた時だけ**効いていた。プレイヤーが部隊全員に
「この敵を攻撃」と命令すると、命令は上書きされない決まりなので全員が `targetId` を持ち、

## 2026-11-04 歩きのもっさり・ドタバタを抑える（`67975f4e`）

### なぜ

ユーザーから「歩きのもっさりとドタバタ感を抑えたい」。ただし**「速く移動させたい」ではない**。

### 調べて分かった原因

`js/render/dolls.js` の歩行アニメ再生速度の決め方に原因があった。

- 再生倍率は `mixer.timeScale = 時間の進み（1/2/3/5）` だけで、**その人の実際の移動速度を見ていなかった**
- 隠密（`SneakWalk`）だけは `velocity × duration ÷ distance` で速度に同期していたが、
  **通常の `Walk` / `Run` は倍率 1.0 固定**。`doll.glb` の解析で `Walk` は 1.333秒、`Run` は 0.917秒、
  どちらも `extras: null`（= `distance` のメタデータが無い）ことを確認
- 歩行速度は `base × legFactor × loadFactor × daze`（`ai.js`）で、**最小 0.1 倍**まで落ちる
