## 2026-11-04 バージョンの上げ方をルール化した（`AGENTS.md` §2 / `CURRENT_WORK.md`）

### なぜ

ユーザーの指示「今後は更新のたびに規模に応じてバージョンNo.も更新」。

### 決めたこと

`<ゲーム>/sw-assets.js` の2つを**毎回**上げる（AGENTS.md §2）。

- `version`（キャッシュ用の連番）は規模に関係なく毎回。`v1` → `v2` → …
- `gameVersion`（ハブのカードに出る版）は規模で選ぶ:
  不具合修正・見た目の微調整・文言＝パッチ `0.1.0`→`0.1.1` ／
  機能追加・仕様変更・バランス調整＝マイナー `0.1.1`→`0.2.0` ／
  大きく作り替えた・区切りがついた＝メジャー `0.2.0`→`1.0.0`

版を上げるのはゲーム側の2行だけで完結する（共有ファイルは触らない）。

`gameVersion` は `common/js/app.js` が `fetch(..., { cache: 'no-cache' })` して
**正規表現 `/gameVersion\s*:\s*['"]([^'"]+)['"]/` で拾う**。書き方を崩すとカードに版が出なくなる。

## 2026-11-04 歩きのもっさり・ドタバタを抑える（`67975f4e`）

### なぜ

ユーザーから「歩きのもっさりとドタバタ感を抑えたい」。ただし**「速く移動させたい」ではない**。

### 調べて分かった原因

`js/render/dolls.js` の歩行アニメ再生速度の決め方に原因があった。

- 再生倍率は `mixer.timeScale = 時間の進み（1/2/3/5）` だけで、**その人の実際の移動速度を見ていなかった**
- 隠密（`SneakWalk`）だけは `velocity × duration ÷ distance` で速度に同期していたが、
  **通常の `Walk` / `Run` は倍率 1.0 固定**。`doll.glb` の解析で `Walk` は 1.333秒、`Run` は 0.917秒、
  どちらも `extras: null`（= `distance` のメタデータが無い）ことを確認
- 歩行速度は `base × legFactor × loadFactor × daze`（`ai.js`）で、**最小 0.1 倍**まで落ちる
  （片脚骨折 0.6 ／ 片脚欠損 0.35 ／ 両脚欠損 0.12 ／ 荷重は容量比 1.2 で 0.15、以降 0.1 で頭打ち ／ 朦朧 0.5 ／ 担ぎ 0.6）
- つまり**荷物を抱えた人は 0.15 倍の速度なのに、脚は 6.7 倍の速さで回っていた**
- 旋回は `MAX_TURN_PER_TICK = 0.22`（126°/秒・**定速**）。180° 反転に 1.43 秒。大きいずれでも小さいずれでも同じ時間

### 直した内容（7ファイル・+148 / -21）

1. **脚を移動速度に同期**（`render/dolls.js` / `render/sneak_pose.js`）
   `distance` が無いので、基準速度で倍率 1.0 になる値を与える（`Walk: 1.6×1.333 = 2.133` / `Run: 3.5×0.917 = 3.208`）。
   毎フレーム `velocity ÷ 基準速度` を掛ける。隠密は従来どおり 0.5〜2.2 のクランプを保つ（見た目を変えない）
2. **旋回を可変に**（`sim/ai.js`）向きのずれが大きいほど速く、走行中はさらに速く
3. **歩けなかった1tickで立ち姿に戻らない**（`settleStopAnim`）。往復を抑える
4. **回り込む側を最低4tick保持**（`passSideUntil`）、**押した時の減速 0.45 の段差を 0.12/tick のランプへ**
5. **歩き出し・止まり際に短い速度の立ち上がり**（0.35〜1.0）。止まり際は2tick続けて動けない時だけ落とすので、
   混雑で1tick止まるだけでは鈍らない
6. 獣の脚も同じく同期（`render/beasts.js`）。名目速度では従来と同じ見た目
7. 上記の一時状態を new/save で欠けないようにする（`sim/world.js` / `sim/save.js`）

### 検証（ヘッドレス Chrome 390×844・serviceWorker無効で配信コードを直接確認）

同じ1人を連続で走らせ、**脚の回転倍率 = 速さ ÷ 基準速度** になることを確かめた
（断続的に動く人や、押し合い・詰まり復帰で動かされた分が混ざらないよう、条件を変えて同じ人で比較した）:

| 条件 | 実測の速さ | 脚の回転倍率 | 期待値 | 差 |
|---|---|---|---|---|
| 健常（走り） | 3.520 m/s（1tick 0.352 m） | 1.006 | 1.006 | 0.000 |
| 両脚を砕いた（脚 0.3倍） | 1.056 m/s | 0.302 | 0.302 | 0.000 |
| 両脚を失った（脚 0.12倍） | 0.423 m/s | 0.121 | 0.121 | 0.000 |

- `Walk` / `Run` の `distance` が入ったこと（2.133 / 3.208）と `SneakWalk` が変わっていないことを確認
- 180° 反転: **3tick**（0.30秒。以前は 14tick = 1.43秒）
- 仲間12人の真ん中を 120tick 歩いて、**歩き↔立ちの往復は 1回**
- 歩き出しの1tickごとの進み: 0.133 → 0.231 → 0.286 → 0.316 → 0.332 → …（定常 0.352）。
  定常値が基準の走り速度 3.5 m/s と一致するので**長距離では速さを損していない**
- ページエラー **0**、フレーム時間 中央値 **16.7ms** / p90 **16.8ms**（60fps 維持）
- 既存の `tests/` **7件 通過**

### 残ったこと

- **iPhone の実機で見ていない**。ユーザーの体感確認待ち
- 獣の脚の同期は数値でしか見ていない（見た目は未確認）
- 検証スクリプトはリポジトリに入れていない（`codex-runtimes` の playwright を絶対パスで参照していて機械依存）。
  手順は [CURRENT_WORK.md](CURRENT_WORK.md) §5 に書いた
