## 2026-11-05 気絶の倒れ方（スケキヨ）・同じ敵への殺到・投げた後の追撃（v5 / 0.4.0）

### なぜ（佳之さんの指摘）

1. 「ノックアウトされた敵がみんなスケキヨみたいになってる」
2. 「間合いを取るって設定した気がするんだけど生きてないな、みんな同じ敵に殺到して密着する」
3. 「格闘で転ばせた後終わった扱いでターゲットはずれてしまうのも直ってない」

### 原因と直し方

**1. スケキヨ（`js/render/dolls.js` / `js/render/ko_collapse.js`）**

2つ原因があった。

- **二重に寝かせていた**: ラグドールが姿勢を地面に伏せたあと、`dolls.js` が
  「倒れクリップが無い時」用に `root.rotation.x = -π/2` でさらに寝かせていた。
  KO は `customDown` が false になったのでこの処理が当たり、**体がもう90°回って脚が上を向いていた**
  （実測: 地面から 足 6.98 / 骨盤 6.21 / 頭 5.59 = 脚が一番高い）。→ ラグドールが居る時は寝かせない
- **全員が同じ姿勢に収束していた**: 倒れ終わりに「Fall クリップの最終フレーム」へブレンドするので、
  経過が違っても最後は全員同じ格好になる。→ 手足（腕・脚）だけ人ごとに ±0.4rad（±23°）ずらす
  （胴＝背骨・首・頭は揃えたままなので、起き上がりの繋がりは崩れない）

**2. 同じ敵への殺到（`js/sim/ai.js`）**

`surround.js` の待ち輪は**自動で狙いを付けた時だけ**効いていた。プレイヤーが部隊全員に
「この敵を攻撃」と命令すると、命令は上書きされない決まりなので全員が `targetId` を持ち、
**枠（同時に斬れる数＝2）も輪も無視して全員が密着していた**（実測: 6人で engaged 6 / 押し合い 6人 /
距離 0.8〜1.4m）。→ 命令で狙っている者にも輪を適用した（`canSurroundWait`）。
狙いは外さないので、枠が空けばそのまま入る。

**3. 投げた後の追撃（`js/sim/commands.js`）**

AI と戦闘の判定は「投げで転んだだけの転倒（`knocked`、意識あり）なら追撃してよい」なのに、
**攻撃命令だけが「倒れている。斬らない」で拒否していた**（`kenshi-next` の
`knockdown.test.mjs` の決まりと食い違い）。→ 命令も `knocked` を除外して、意識がある転倒は追撃可に。

### どう確かめたか（実測）

- ラグドール: ヘッドレスで人形を4体作り、頭に `hp + max*0.3` のダメージで気絶させて240フレーム回した。
  地面からの高さが 足 0〜0.11 / 骨盤 0.06 / 頭 0.16〜0.17、`rootRotX = 0`、骨盤より高い所は 0.11〜0.14m で
  **伏せたまま・脚は上を向かない**。手足の高さが人ごとに違う（足 0.11/0.11、0.05/0.04、0/0.08、0.11/0.04）ことも確認
- 殺到: 味方6人 対 敵1人を sim で回した（`makeActor` で味方を追加）。
  - 自動で交戦: 交戦2人（1.2〜1.4m）＋ 待ち4人（4.5〜4.9m）＝**輪が効いている**（元から）
  - 全員に攻撃命令: **交戦6人・押し合い6人（0.8〜1.4m）** ＝殺到（これが指摘の状態）
  - 修正後: 交戦2人（1.2〜1.4m）＋ 輪で待つ4人（4.4〜4.7m）、`orderedTargetId` は6人とも保持
- 投げ: 決闘を sim で回し、投げた後の `attacker.targetId` が外れないこと（t=43〜115 で targetId 9 のまま）を確認
- テスト: リポジトリ内 **29件 通過**。ハーネス全件は HEAD 比で**意図した1件（自動の担ぎ）だけ**増（1116件中 1079 合格）

### 残ったこと

- 「壁に引っかかってガクガク」は未着手（`collide.js` の壁ずり＋`ai.js` の押し合いの詰まりの見直し）
- 実機（iPhone）での体感確認は未実施

## 2026-11-05 気絶の倒れ方（ラグドール）・命令なしの担ぎ・暗殺の到達・体の窓（v3 / 0.3.0）

### なぜ（佳之さんの指摘）

1. 「ノックダウン時のラグドールが反映されてないように見える」＝気絶した時に従来のダウン動作が出る
2. 「抱えた仲間を下ろすとTポーズになる。下ろした仲間が意識があるなら普通に直立、意識がないならラグドール」
   ／「そもそも担ぐ命令を出してないのに仲間が担いでたのも変」
3. 「暗殺選ぶといつ迄たっても対象にたどり着けない」「たどり着いても暗殺実行しない」
4. 「この体の詳細の折り畳みはいらない。普通に体力バーとか表示でいい」
5. 「赤いゲージは kenshi だと出血部。出血がなくて最大値が減ってるなら赤い部分はなくてバー全体が減る形でいい。
   右端の現在地/最大値はいらなくて現在値だけでいい」

### 原因と直し方

**1. ラグドール（`js/render/dolls.js`）**

`sim/body.js` の `knockOut()` は気絶した者に `maDownClip = 'Knocked Out'` を入れる。
人形側は `customDown`（専用の倒れクリップがある）と見なしてラグドールを止めていたので、
**台本付きの「立ち姿から倒れる」クリップが再生され、ラグドールは一度も走っていなかった**。

sim の値は変えず（`ma_rest1.test.mjs` が `'Knocked Out'` を期待している）、**人形側だけ**で
`KO_CLIP = 'Knocked Out'` を「専用クリップ無し」として扱うようにした（`customDown` と `customMotion` の2箇所）。
あわせて、意識のある転倒（`knocked`）と投げの受け身中（`martialRecovery`）はラグドールにしない
（ラグドールは `state === 'dead'` か、`!knocked && !martialRecovery` の時だけ）。

**2. 担ぎ（`js/sim/carry.js` / `js/render/dolls.js`）**

- `updateCompanionCarry` が「敵が見えず、他の命令が無ければ最寄りの倒れた味方（30m以内）を自動で担ぐ」
  という探索を持っていた。これが指摘の「命令なしで勝手に担ぐ」。**探索を削除**し、担ぐのは
  `commands.js` の `pickup` 命令（`carryTargetId` + `carryOrdered`）だけにした
- Tポーズ: 担がれている間は `doll.wasDown = false` にして「倒れ始め」を忘れ、**下ろした瞬間に
  もう一度ラグドール／通常の倒れを始める**ようにした（`doll.wasDown = actor.carriedBy != null ? false : down`）

**3. 暗殺（`js/sim/stealth.js`）**

- 寄る時の速度が `1.6 * 0.7 = 1.12`（隠密歩き）で、**歩いている相手（1.6）に追いつけなかった** → 通常の歩き速度 `1.6` に
- 背後を取れている間だけ `assassinTicks` を増やし、**1 Tick でも外れると 0 に戻していた**ので、
  動く相手には永久に実行できなかった → 進捗は少しずつ戻すだけにし、**2秒（20 Tick）隣に付けていれば
  背後を取れなくても押さえ込んで実行**するようにした
- 回り込む向きを Tick ごとに決め直していたのを、**対象ごとに一度だけ決めて保持**（`assassinSideFor` / `assassinSide`）

**4・5. 体の窓（`js/ui/hud.js` / `js/ui/health_ui.js` / `css/style.css`）**

- 「体の詳細」ボタンと折り畳みを削除。`kb-box` は常に表示（`hp-details` の CSS も削除）
- 部位バーの赤は**出血している部位だけ**（`partBleeding`）。出血していない傷（最大値が下がった分）は
  赤も斜線も描かず、**バーが短くなる**形にした（`.kb-wound` の幅を常に 0）
- 右端の数字は現在値だけ。`limbBar` / `bloodBar` の `text`（今/最大）はテストの契約なので残し、
  画面が使う `textNow`（今だけ）を足して HUD はそちらを使う

### どう確かめたか

- `node --test kenshi-next/tests/*.test.mjs` → **29件 通過**
- ハーネス全件（`run_tests.sh`）→ 1116件中 1079 合格。**HEAD と作業ツリーの失敗一覧を比べて、
  増えたのは意図した1件だけ**（「相棒は敵がいなければ倒れた仲間を担ぐ」＝自動の担ぎをやめたため。
  `baseline_failures.txt` に理由を書いて足した）。baseline 自体が 11/03 のままで古く、
  HEAD 単体でも 36 件が baseline 外で落ちるので、比較は HEAD を基準にした
- ラグドール: ヘッドレスで人形を作り、頭を `hp + max*0.3` のダメージで気絶させて 180 フレーム回した。
  `doll.ko.phase` が `fall → blend → done` と進み、`animName` が `Knocked Out` になることは一度も無かった。
  担ぎ中は `wasDown=false, ko=null` → 下ろした直後のフレームで `ko='fall'` に切り替わることも確認
- 暗殺: `node --input-type=module` で 前・左・右・後 の4方向から `updateAssassination` を回し、
  4方向とも解決することを確認（動く相手（向きを変えながら離れる）でも 25 Tick で解決）
- 体の窓: ローカル配信をヘッドレスで開き、`select()` で選んで DOM を直接読んだ。
  出血なし → 頭 `num:42` `green:42%` `red:0%`、出血あり → 頭 `red:36.2%` / 胸 `red:70%`。
  `.hp-details` は 0 個、`kb-box.hidden` は false。数字は「42/84」ではなく「42」
- レイアウト: 390×844 / 844×390 / 1366×800 のどれでもパネル（186×108）が画面からはみ出さない
- ページ確認（`pagecheck.sh`、PC 1366×800 とスマホ 390×844）: 2行とも `game True tick>0 errors []`

## 2026-11-04 バージョンの上げ方をルール化した（`AGENTS.md` §2 / `CURRENT_WORK.md`）

### なぜ

ユーザーの指示「今後は更新のたびに規模に応じてバージョンNo.も更新」。

### 決めたこと

`<ゲーム>/sw-assets.js` の2つを**毎回**上げる（AGENTS.md §2）。

- `version`（キャッシュ用の連番）は規模に関係なく毎回。`v1` → `v2` → …
- `gameVersion`（ハブのカードに出る版）は規模で選ぶ:
  不具合修正・見た目の微調整・文言＝パッチ `0.1.0`→`0.1.1` ／
  機能追加・仕様変更・バランス調整＝マイナー `0.1.1`→`0.2.0` ／
  大きく作り替えた・区切りがついた＝メジャー `0.2.0`→`1.0.0`

版を上げるのはゲーム側の2行だけで完結する（共有ファイルは触らない）。

`gameVersion` は `common/js/app.js` が `fetch(..., { cache: 'no-cache' })` して
**正規表現 `/gameVersion\s*:\s*['"]([^'"]+)['"]/` で拾う**。書き方を崩すとカードに版が出なくなる。

## 2026-11-04 歩きのもっさり・ドタバタを抑える（`67975f4e`）

### なぜ

ユーザーから「歩きのもっさりとドタバタ感を抑えたい」。ただし**「速く移動させたい」ではない**。

### 調べて分かった原因

`js/render/dolls.js` の歩行アニメ再生速度の決め方に原因があった。

- 再生倍率は `mixer.timeScale = 時間の進み（1/2/3/5）` だけで、**その人の実際の移動速度を見ていなかった**
- 隠密（`SneakWalk`）だけは `velocity × duration ÷ distance` で速度に同期していたが、
  **通常の `Walk` / `Run` は倍率 1.0 固定**。`doll.glb` の解析で `Walk` は 1.333秒、`Run` は 0.917秒、
  どちらも `extras: null`（= `distance` のメタデータが無い）ことを確認
- 歩行速度は `base × legFactor × loadFactor × daze`（`ai.js`）で、**最小 0.1 倍**まで落ちる
  （片脚骨折 0.6 ／ 片脚欠損 0.35 ／ 両脚欠損 0.12 ／ 荷重は容量比 1.2 で 0.15、以降 0.1 で頭打ち ／ 朦朧 0.5 ／ 担ぎ 0.6）
- つまり**荷物を抱えた人は 0.15 倍の速度なのに、脚は 6.7 倍の速さで回っていた**
- 旋回は `MAX_TURN_PER_TICK = 0.22`（126°/秒・**定速**）。180° 反転に 1.43 秒。大きいずれでも小さいずれでも同じ時間

### 直した内容（7ファイル・+148 / -21）

1. **脚を移動速度に同期**（`render/dolls.js` / `render/sneak_pose.js`）
   `distance` が無いので、基準速度で倍率 1.0 になる値を与える（`Walk: 1.6×1.333 = 2.133` / `Run: 3.5×0.917 = 3.208`）。
   毎フレーム `velocity ÷ 基準速度` を掛ける。隠密は従来どおり 0.5〜2.2 のクランプを保つ（見た目を変えない）
2. **旋回を可変に**（`sim/ai.js`）向きのずれが大きいほど速く、走行中はさらに速く
3. **歩けなかった1tickで立ち姿に戻らない**（`settleStopAnim`）。往復を抑える
4. **回り込む側を最低4tick保持**（`passSideUntil`）、**押した時の減速 0.45 の段差を 0.12/tick のランプへ**
5. **歩き出し・止まり際に短い速度の立ち上がり**（0.35〜1.0）。止まり際は2tick続けて動けない時だけ落とすので、
   混雑で1tick止まるだけでは鈍らない
6. 獣の脚も同じく同期（`render/beasts.js`）。名目速度では従来と同じ見た目
7. 上記の一時状態を new/save で欠けないようにする（`sim/world.js` / `sim/save.js`）

### 検証（ヘッドレス Chrome 390×844・serviceWorker無効で配信コードを直接確認）

同じ1人を連続で走らせ、**脚の回転倍率 = 速さ ÷ 基準速度** になることを確かめた
（断続的に動く人や、押し合い・詰まり復帰で動かされた分が混ざらないよう、条件を変えて同じ人で比較した）:

| 条件 | 実測の速さ | 脚の回転倍率 | 期待値 | 差 |
|---|---|---|---|---|
| 健常（走り） | 3.520 m/s（1tick 0.352 m） | 1.006 | 1.006 | 0.000 |
| 両脚を砕いた（脚 0.3倍） | 1.056 m/s | 0.302 | 0.302 | 0.000 |
| 両脚を失った（脚 0.12倍） | 0.423 m/s | 0.121 | 0.121 | 0.000 |

- `Walk` / `Run` の `distance` が入ったこと（2.133 / 3.208）と `SneakWalk` が変わっていないことを確認
- 180° 反転: **3tick**（0.30秒。以前は 14tick = 1.43秒）
- 仲間12人の真ん中を 120tick 歩いて、**歩き↔立ちの往復は 1回**
- 歩き出しの1tickごとの進み: 0.133 → 0.231 → 0.286 → 0.316 → 0.332 → …（定常 0.352）。
  定常値が基準の走り速度 3.5 m/s と一致するので**長距離では速さを損していない**
- ページエラー **0**、フレーム時間 中央値 **16.7ms** / p90 **16.8ms**（60fps 維持）
- 既存の `tests/` **7件 通過**

### 残ったこと

- **iPhone の実機で見ていない**。ユーザーの体感確認待ち
- 獣の脚の同期は数値でしか見ていない（見た目は未確認）
- 検証スクリプトはリポジトリに入れていない（`codex-runtimes` の playwright を絶対パスで参照していて機械依存）。
  手順は [CURRENT_WORK.md](CURRENT_WORK.md) §5 に書いた
