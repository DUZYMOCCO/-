## 1. Phase 0：既存環境調査と技術選定の根拠

詳細は [PHASE0_ARCHITECTURE.md](./PHASE0_ARCHITECTURE.md) を参照。

- **現行 `abyss-dive` の構造**: 依存なし HTML5 Canvas2D（`1280×720`、`sunken-city.webp` 1枚の反転タイリング＋1/2解像度単一暗幕 `darkCv` による `destination-out` 穴抜き）。ズーム未実装。奥行きに応じた照光・遮蔽影・法線陰影・多層霧の実装が構造上困難。
- **採用技術**: **依存ゼロの独自軽量 WebGL2（GLSL ES 3.00）多層レンダラ**
  - iOS Safari（iPhone 17 / Metal-ANGLE）で WebGL2 は安定・高速。
  - Canvas2D では 15〜30 層の法線照光・5グループ空間ライト・遮蔽シャドウ・屈折・光散乱を `1748×804 @ 60FPS` で維持できない。
  - PixiJS / Three.js 等の外部ライブラリは本計画の中核（5グループ空間ライト補間＋遮蔽レイマーチ＋Depth Stacking）に結局カスタムシェーダーが必要であり、ゼロ依存 PWA の軽量性と将来の既存ゲーム統合（Phase 5：背景/世界のみ WebGL2 化＋UI は現行維持）の観点で独自 WebGL2 が最適。

## 2. Phase 1：構築した独立プロトタイプ（`abyss-dive/depth-lab/`）

### 2.1 ファイル構成
- `index.html` / `css/lab.css`: 描画解像度と完全分離されたネイティブ DOM デバッグ UI
- `js/depth-math.js`: 統一ワールド座標 `(wx, wy, wz)` 投影・ズーム整合・5〜30 層構成・5 ライティンググループ連続補間・時間連続性（純粋 ES モジュール、`tests/depth-math.test.mjs` で全6テスト通過）
- `js/shaders.js` / `js/renderer-webgl2.js`: 5 パス WebGL2 レンダラ
  1. **Occluder Pass**（低解像度 `437×201` + 深度バッファ）：巨大生物・遺跡アーチ・岩壁の遮蔽マスク生成
  2. **5-Group Light Atlas Pass**（標準 `874×402 × 5` を 3×2 アトラス 1 枚に描画）：Tier 1 高品質光源（最大6）＋Tier 2 簡易光源（10）＋Tier 4 環境光＆コースティクス＋11 ステップ深度比較ソフトシャドウ＋水中光散乱
  3. **Depth Stacking Layer Pass**（`874×402` / `1748×804` / `2622×1206` 切替可）：5〜30 層奥→手前描画、隣接 2 ライトグループ連続補間（境界段差ゼロ）、ノーマルマップ指向性立体照光、12×12 サブディビジョン共有メッシュによる水流揺れ＆遊泳波動、水中屈折、疑似深度ボケ、Beer-Lambert 濁り＆インスキャタリング、4 深度帯域インターリーブ浮遊粒子（ライトバッファから直接照光）、遮蔽反応ボリュメトリック光条
  4. **Bloom Pass**（1/4 解像度セパラブルガウスブラー）
  5. **Composite Pass**（ACES 近似トーンマップ＋ヴィネット＋デバッグ可視化切替）
- `js/scene-builder.js`: 11.7 品質検証用シーン（巨大海溝・沈没遺跡アーチ・玄武岩崖・揺れる巨大ケルプ・発光サンゴ・琥珀ポリプ岩・垂れ下がる深海天蓋・複数奥行きの深海魚群・動的光源を帯同して泳ぐ発光クラゲ・光源を遮る2体の巨大マンタ・操作可能な潜水艇 09）
- `js/debug-ui.js`: 要件 8 の全調整項目・カメラ比較プリセット・5 群ライト/遮蔽マスク可視化・ワンクリック 5〜30 層ベンチマーク
- `tools/process_assets.py`: 白/黒背景デマット切り出し（白縁完全除去）・タイトクロップ・マルチスケール Sobel ノーマルマップ生成・発光マップ抽出パイプライン（13 アセット＋ノーマル 9 枚＋発光 7 枚）
- `tools/serve.py`: ローカル起動用 HTTP サーバ（Windows `.js` MIME 問題回避済み）

## 4. 性能測定結果（PC / Chromium 実測値）

### 4.3 高品質光源数別ベンチマーク（15層, 1748×804）
0灯 / 2灯 / 4灯 / 6灯すべてで 60FPS 張り付き（5ライト群アトラスの固定 5 パス構成により、レイヤー数×光源数の計算爆発が抑制されている）。

### 4.4 定量分析
- タイトクロップ＋疎密構図により、**15 層でも実効オーバードローは `3.06x`（30 層でも `3.60x`）** に抑えられた。全面透明テクスチャ 15 枚重ね（`15.0x`）比で約 1/5 のフィルレート負荷。
- VRAM は 15 層標準で `76.8MB`（未圧縮 RGBA 展開＋RGBA16F FBO 込み）。iPhone 17 実機に向けてテクスチャアトラス化・KTX2/ASTC 圧縮を導入すれば 30MB 以下まで削減可能。

## 5. 今後の課題（Phase 2〜4 への接続）

1. **Draw Call バッチング（インスタンシング / テクスチャアトラス）**: 現状 15 層で 126 Draw Calls（魚群や同素材も個別描画）。魚群・同アセットのインスタンシング描画へ統合すれば 35〜45 Draw Calls まで圧縮でき、iPhone 17 の発熱・消費電力がさらに下がる。
2. **Phase 2 深化（光の生命感と異世界観プリセット）**:
   - 巨大生物が光源の前を横切った際の「岩肌へ落ちる影」のさらなるコントラスト演出（現状ライトバッファ上の影は鮮明だが、背景アーチ越しに落ちるボリュメトリック・ゴッドレイ影を強調できる）。
   - 要件 4.5 の世界観別ライティングプリセット（人類文明の残骸 / 異常進化生態系 / マントル領域 / ブラックホール重力レンズ歪み / 木星内部の海）の検証追加。
3. **Phase 3（素材多層化パイプラインの高度化）**:
   - 1 枚の高品質背景原画から AI デプスマップ推定（Depth Anything V2 等）＋セグメンテーション＋インペインティング補完で多層素材を自動出力するツール研究、およびピクセル単位デプスマップ視差の比較検証。
4. **Phase 4（iPhone 17 実機検証）**:
   - WebGL Inspector / Safari Web Inspector の GPU タイムラインを使い、iPhone 17 実機で 1748×804 vs 874×402、ライトバッファ 874×402 vs 437×201、20〜30 分連続稼働時の発熱とフレーム時間ばらつきを実測する。
