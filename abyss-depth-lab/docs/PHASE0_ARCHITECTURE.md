作成日: 2026-11-25
対象: `abyss-dive/depth-lab/`（既存 `abyss-dive/` 本番環境から完全隔離された独立研究プロトタイプ）

## 1. Phase 0：既存環境の調査結果

### 1.1 現行 `abyss-dive` の描画アーキテクチャ
- **実行環境**: ブラウザ向け静的 PWA（GitHub Pages 配信、依存ライブラリなし、純 ES モジュール）。
- **描画方式**: 単一 HTML5 Canvas2D（`js/game.js`, `ctx = cvs.getContext('2d', { alpha: false })`）。
  - 論理解像度 `1280×720`、`dpr = Math.min(devicePixelRatio, 1.5)` で全画面フィット。
  - v1.16.1 にて Three.js 経路を廃止し Canvas2D へ一本化済み。
- **カメラ・ズーム**: `camX, camY` の 2D 平行移動のみ。動的ズームは未実装。
- **現行の背景描画（`drawBackground`）**:
  - 1枚の不透明イラスト `assets/sunken-city.webp`（1536×851）を反転タイリング（視差係数 `0.40`）で描画。
  - その上にプロシージャルな三角形尖塔（`0.55`）・簡易魚群（`0.38`）・エイシルエット・マリンスノー・均一暗幕 `drawDepthScrim` を重ねる構成。
- **現行のライティング（`drawLighting` / `drawGlowPass` / `drawDeepWatch`）**:
  - 1/2 解像度（`640×360`）の単一オフスクリーン Canvas `darkCv` に暗幕を塗り、`destination-out` で光源の穴を開けて全画面へ一括合成。
  - 深い区間では `litMaskCv` + `litDetailCv` による `destination-in` 抜きを追加しているが、**画面空間での一律処理**であり、以下が構造上困難：
    1. 光源の奥行き位置に応じた他レイヤーへの減衰・照光
    2. ノーマルマップによる岩肌・遺跡・船体の立体陰影
    3. 巨大生物や岩柱が光源を遮って背景へ落とす影
    4. レイヤーごとの濁り・ぼかし・水流屈折・色調制御
    5. 15〜30 層の多層空間を 1748×804 @ 60FPS で低発熱維持すること

### 1.2 iOS / iPhone 17 Safari における利用可能技術
- **WebGL2（GLSL ES 3.00）**: iOS 15 以降で完全サポート。ANGLE 経由で Apple GPU（Metal）へ変換され、FBO マルチパス・MRT・浮動小数点/ハーフ浮動小数点テクスチャ・インスタンシングが安定して高速に動作する。
- **WebGPU**: 最新世代 iOS で展開中だが、ブラウザ実装差・シェーダー保守性・既存 PWA との互換性の面で、現段階の主軸は **WebGL2** が最も堅実（将来的なバックエンド抽象化も容易）。
- **解像度分離**: WebGL2 キャンバス（内部描画解像度を `874×402` / `1748×804` / `2622×1206` で任意設定）と、UI/デバッグオーバーレイ（DOM/CSS または別 Canvas2D）を完全に分離可能。

## 2. 技術選定比較と根拠

| 観点 | Canvas2D 拡張 | PixiJS v8 / Three.js | **独自軽量 WebGL2（採用）** |
| :--- | :---: | :---: | :---: |
| 15〜30層 + ノーマル/散乱/遮蔽 @ 60FPS | ×（fill-rate/CPU限界） | ○（ただしカスタムシェーダー必須） | **◎（最小パス・バッチ直結）** |
| 描画レイヤーと 5 ライティンググループの分離 | × | △（抽象化が逆に煩雑） | **◎（FBO 構成を直接設計）** |
| 外部依存・PWA キャッシュ負荷 | ◎（0KB） | △（数百KB〜の依存追加） | **◎（0依存、数十KB）** |
| 既存ゲーム（Phase 5）へのハイブリッド統合 | ◎ | △ | **◎（背景+世界を WebGL2、UI は現行維持可）** |
| シェーダー・ライトバッファの実験柔軟性 | × | ○ | **◎（全パラメータ即座に制御可能）** |

**採用結論**: **依存ゼロの純 ES モジュール WebGL2 レンダラ（Depth Stacking Engine）**を採用する。
なお、本選定は Phase 1〜4 の実測結果に応じて見直し可能な仮説であり、プロトタイプ内でフレーム時間・ドローコール・オーバードロー推定・VRAM 消費を定量計測する。

## 3. Depth Stacking + 空間ライティング アーキテクチャ設計

### 3.1 統一ワールド座標系と透視投影パララックス（要件 4.1, 11.3）
すべてのレイヤー、個別オブジェクト、光源、遮蔽体、浮遊粒子を単一の 3D ワールド座標 `(wx, wy, wz)` で管理する。

- `wz > 0`: 操作層より奥（遠景・最遠景、`wz ∈ (0, 12]`）
- `wz = 0`: 操作層（潜水艇・敵・資源）
- `wz < 0`: 操作層より手前（前景・最前景、`wz ∈ [-0.55, 0)`）

仮想カメラ距離を $D$（標準 `2.6`）、パララックス強度を $k_p$（標準 `1.0`）、カメラ座標を $(C_x, C_y)$、ズーム倍率を $Z_{\text{cam}}$ とすると、奥行き $w_z$ における視差・透視スケール係数は次式で一意に決まる：

$$p(w_z) = \frac{D}{\max(0.25,\ D + w_z \cdot k_p)}$$

オブジェクトおよび光源の画面投影座標（仮想論理座標 `1748×804` 基準）：

$$x_s = (w_x - C_x) \cdot p(w_z) \cdot Z_{\text{cam}} + \frac{W}{2}$$
$$y_s = (w_y - C_y) \cdot p(w_z) \cdot Z_{\text{cam}} + \frac{H}{2}$$
$$\text{scale}_s = p(w_z) \cdot Z_{\text{cam}} \cdot s_{\text{depth}}(w_z)$$

**利点**:
1. ズーム変更時にすべてのレイヤー・光源・遮蔽体・粒子が同一の光学中心から整合して拡縮し、位置関係が破綻しない。
2. レイヤー数を `5〜30` の間で任意変更しても、奥行き $w_z$ の連続空間上に再配置されるため空間構造が維持される。
3. 個別オブジェクトを固定レイヤー間の中間 $w_z$ へ自在に配置可能。

### 3.2 描画レイヤー（5〜30層可変）とライティンググループ（5グループ）の分離（要件 3.1, 11.1）

標準 15 層の初期割り当てと 5 ライティンググループの対応：

| 区分 | 標準層数 | 深度 $w_z$ 帯域 | 主な描画対象 | 対応ライティンググループ |
| :--- | :---: | :---: | :--- | :--- |
| 最遠景 | 1 | `9.5` | 巨大海溝・遠方の水柱光 | Group 0 (`z_g = 7.5`) |
| 遠景 | 3 | `6.2, 4.4, 3.1` | 巨大山脈・遠方遺跡・遠景巨大生物 | Group 0 ↔ Group 1 (`z_g = 3.0`) |
| 中景 | 3 | `2.2, 1.5, 0.95` | 岩壁・巨大石造アーチ・遮蔽巨大生物・生態系 | Group 1 ↔ Group 2 (`z_g = 1.1`) |
| 近景 | 3 | `0.62, 0.36, 0.16` | 岩礁・揺れる海藻・発光サンゴ・魚群・発光生物 | Group 2 ↔ Group 3 (`z_g = 0.0`) |
| 操作層 | 1 | `0.0` | 潜水艇 09・近接粒子・操作空間の光源 | Group 3 (`z_g = 0.0`) |
| 前景 | 3 | `-0.14, -0.26, -0.38` | フレーミング岩壁・手前海藻・横切る魚 | Group 3 ↔ Group 4 (`z_g = -0.35`) |
| 最前景 | 1 | `-0.48` | 近接浮遊物・ボケ表現 | Group 4 (`z_g = -0.35`) |

- **境界の分断を防ぐ隣接グループ連続補間**:
  - 5 つのライティンググループはそれぞれ低解像度（標準 `874×402`）のライトテクスチャ（5 スライス／または 1 枚の `2×3` アトラス FBO）へ事前描画される。
  - 各描画レイヤー（深度 $w_z$）は、自分の $w_z$ を挟む隣接 2 グループ $g_a, g_b$ を滑らかな重み $w = \text{smoothstep}(z_{g_a}, z_{g_b}, w_z)$ で線形補間してサンプリングする。
  - これにより、**照明計算負荷はレイヤー数に比例せず 5 グループ一定**のまま、15 層〜30 層の間に一切の明暗段差を生じない。

### 3.3 光源の品質階層化（要件 11.2）

1. **Tier 1：高品質動的光源（標準 2〜4 個、最大 6 個）**
   - ワールド座標 `(lx, ly, lz)`、色、強度、到達距離、照射角/方向、Z 減衰係数を持つ。
   - **役割**:
     - 全レイヤーのシェーダーへ uniform 配列で直接供給し、**ノーマルマップとの内積 `dot(N, L)` による立体照光**をピクセル単位で計算。
     - **遮蔽マスク（Occluder FBO）に対する放射レイマーチシャドウ**により、巨大生物や岩柱が光源を横切ると周囲に動的な影を落とす。
     - ボリュメトリックな水中光散乱（ゴッドレイ／ヘッドライト光条）と粒子照光を生成。
   - 検証シーンの初期構成（4個）:
     1. 潜水艇ツインヘッドライト（スポットコーン＋近傍ハロー）
     2. 発光遊泳生物（中景〜近景を独立軌道で泳ぎ、岩肌と海藻を照らす発光クラゲ）
     3. 遺跡共鳴コア / 熱水光（中景アーチ奥で緩やかに呼吸する暖〜青緑の環境光源）
     4. 探索発光エイ / 第4動的光源（デバッグ UI で 1〜6 個に可変）
2. **Tier 2：簡易光源（8〜16 個）**
   - 5 つの低解像度ライトバッファへ加算描画。遠方の遺跡灯・発光珊瑚群・熱水の揺らぎ光を低コストに表現。
3. **Tier 3：発光オブジェクト（30〜60 個）**
   - 各素材の発光マップ（Emissive Map）および発光胞子・魚群発光点として描き、低解像度ブルームパスで柔らかく滲ませる。
4. **Tier 4：環境光（Water Column + Caustics）**
   - カメラ深度・奥行き $w_z$ に応じた深海光減衰（Beer-Lambert 近似：赤が最も早く消え、青緑が残る）＋緩やかな海面コースティクス揺らぎ。

### 3.4 レンダリングパイプライン（1 フレームのパス構成）

1. **Pass 1：遮蔽マスク生成（Occluder Buffer, `437×201` R8/RGBA8）**
   - 遮蔽属性を持つオブジェクト（巨大生物、主要岩壁・遺跡柱）を、その奥行き $w_z$ をエンコードして低解像度バッファへ描画。
2. **Pass 2：5 グループ空間ライトバッファ（Light Atlas FBO, 標準 `874×402` 相当）**
   - 各グループ深度 $z_g$ ごとに、Tier 1＋Tier 2 光源からの入射光、奥行き減衰、および Pass 1 遮蔽マスクによるソフトシャドウ（放射 8〜10 ステップ）＋水中光散乱を焼き込む。
3. **Pass 3：多層 2D 本体描画（Scene FBO, 標準 `1748×804`, `874×402` / `2622×1206` 切替可）**
   - 奥（最遠景）から手前（最前景）へソート描画（空レイヤー・画面外オブジェクトは CPU カリングで除外）。
   - 各オブジェクトのフラグメントシェーダーで以下を統合計算：
     - 補助マップ対応（Color / Normal / Emissive）
     - 水流による頂点揺れ（植物・海藻）および水中屈折 UV 歪み
     - 隣接 2 ライティンググループの連続補間光 ＋ Tier 1 高品質光源による法線立体照光＋遮蔽影
     - 奥行きに応じた水中濁り（Beer-Lambert 色吸収＋散乱フォグ）・彩度/明度・疑似ぼかし
     - 発光マップ出力（原画の美しい陰影を保持したまま動的光を融合）
   - 各奥行き帯域の間に、対応する深度の浮遊粒子（マリンスノー＋光散乱反応）と魚群・ボリュメトリック光条をインターリーブ描画。
4. **Pass 4：発光抽出・低解像度ブルーム（`437×201` ピンポンブラー）**
   - 発光オブジェクトと強い水中光散乱を滑らかに広げる。
5. **Pass 5：最終合成＆トーンマッピング（ACES 近似＋微細な水中ヴィネット）**
   - 内部解像度の Scene FBO ＋ Bloom を画面へ出力。UI/デバッグパネルは DOM 側でネイティブ解像度描画。

### 3.5 素材と補助テクスチャの分離パイプライン（要件 11.4）
- 各アセットは以下のセットで管理（補助マップは省略可能）：
  - `*_color.webp`: 透過処理・デフリンジ・タイトクロップ済みカラー原画
  - `*_normal.webp`: 原画の輝度勾配＋マルチスケール Sobel から生成した法線マップ（動的ライトが岩肌・遺跡彫刻・潜水艇リベットに沿って陰影を作る）
  - `*_emissive.webp`: 発光部位のみを抽出した発光マップ（潜水艇の窓/灯火、サンゴ発光体、巨大生物の発光斑）
- 原画の静的な陰影を壊さないため、シェーダー側では **「原画ベース照明の保持率 (`ambientPreserve`)」＋「法線照光の加算寄与」** のバランスを調整可能とする。

### 3.6 時間的な連続性（要件 11.5）
- すべてのアニメーション（植物揺れ、魚群、巨大生物の回遊、発光生物の軌道、明滅、粒子、コースティクス）は、単調増加の `worldTime`（フレーム毎 `dt` 積分、`dt <= 0.05` クランプ）と個体ごとの無理数比周波数・決定論的シードで駆動。
- カメラ移動によるリセット禁止。画面外に出た個体もワールド座標上で移動し続け、境界では滑らかにフェードする。

### 3.7 懸念事項と検証ポイント（Phase 1〜4 で確認）
1. **iOS Safari でのフィルレートと発熱**: 15〜30 層のオーバードロー面積比と、1748×804 vs 874×402 の実測フレーム時間を比較する。
2. **ノーマルマップの原画調和**: 自動生成法線が原画の絵画的陰影と喧嘩しない強度（`normalStrength`）を見極める。
3. **遮蔽シャドウの境界品質**: 低解像度遮蔽バッファで巨大生物の影がジャギーにならないブラー／ディザリングを検証する。
4. **実機検証の境界**: 開発環境（Windows + Chromium）での測定値は PC/GPU 計測値であり、iPhone 17 実機測定値とは明確に区別して記録する。
