# 敵の増援と負荷計測（v0.29.0）

2026-10-28 / Windows、Chrome headless、1280×720、DPR 1、通常画質。WebGL は RTX 2070 SUPER / ANGLE Direct3D11 を使用。

## 比較条件

街マップで仲間5人（警察ロボ、アーミーロボ、警察官、アオ、モモ）とミニガン連射を継続。通常敵と特殊敵を混ぜ、画質自動低下を固定して比較した。
敵とプレイヤーのダメージを無効化し、生存数を一定に維持。各条件で2秒ウォームアップ後、5秒間記録。音はミュート。

全条件でプレイ中を維持し、仲間5人の発砲とプレイヤーの弾消費を確認。例外なし。描画送信時間はCPU側の計測で、GPU実行時間そのものではない。
数値の小差には敵の位置や初期化・実行のばらつきが含まれる。80体のほうが軽いという意味ではない。

## 採用した増加

- 同時出現上限は40→48体（20%増）。通常敵のウェーブ総数上限は130→180体。ボスは従来どおり別枠。
- ウェーブ1〜4の総数は維持し、5以降で追加の増援を段階的に増やす。
- 遠方モデルのまとめ描画、思考頻度の調整、近距離の影とパーティクル上限は継続。
- 重い端末で出現上限を下げる段階では、従来と同じ32体・26体へ戻す。30fps固定時には出現数を落とさない既存方針も維持。

## 計測の限界

PC上の短時間比較。iPhone/Safari・低性能スマホ・長時間プレイ・音声負荷・爆発による大量撃破はこの比較に含めていない。
60fpsは表示上限であり、それ以上の余力や端末共通の安全上限は測定できていない。スマホで80体が安定すると判断する根拠には使わない。

## 変更後の動作確認

自動テスト243件通過。通常のウェーブ生成処理でウェーブ12・総数112体・同時48体・待機64体を確認。負荷段階4は32体、段階5は26体。
別のブラウザ試験でロケット爆発を3回発生させ、車両の誘爆を含む37体撃破と、エフェクトの上限内の動作を確認。例外なし。これは動作確認であり、大量撃破時の継続fpsの計測ではない。
